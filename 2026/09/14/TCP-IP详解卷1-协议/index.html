TCP/IP详解 卷1：协议

TCP/IP详解 卷1：协议

作者：W. Richard Stevens（W·理查德·史蒂文斯），第二版更新：Kevin R. Fall
全书共705页，TCP/IP协议领域的圣经级经典教材，深入剖析TCP/IP协议族的每个协议，从链路层到应用层，配合大量实际抓包案例，是理解网络协议本质的必读之作。

第1章 概述

TCP/IP协议族

TCP/IP的历史：

  • 起源于ARPANET（美国国防部高级研究计划局网络）
  • 1969年ARPANET建立，最初4个节点
  • 1970年代TCP/IP协议开发
  • 1983年ARPANET正式切换到TCP/IP
  • 1980年代末互联网爆发式增长
  • TCP/IP成为互联网的事实标准

TCP/IP协议族的分层：

  • 应用层：Telnet、FTP、SMTP、DNS、HTTP等
  • 传输层：TCP（传输控制协议）、UDP（用户数据报协议）
  • 网络层：IP（网际协议）、ICMP（网际控制报文协议）、IGMP（网际组管理协议）
  • 链路层：设备驱动程序、网卡、以太网、WiFi等
  • 与OSI七层模型的对应关系

TCP/IP的特点：

  • 端到端原则：智能放在端系统，网络保持简单
  • 无连接的网络层（IP），可靠的传输层（TCP）
  • 协议族设计简洁、可扩展
  • 与硬件无关，可运行在各种物理网络上

互联网的地址

IP地址：

  • IPv4：32位地址，通常表示为点分十进制（如192.168.1.1）
  • 网络号+主机号
  • 分类地址：A类（0开头，8位网络号）、B类（10开头，16位网络号）、C类（110开头，24位网络号）、D类（1110，组播）、E类（1111，保留）
  • 特殊地址：0.0.0.0（本主机）、255.255.255.255（广播）、127.x.x.x（环回）、10.x.x.x/172.16-31.x.x/192.168.x.x（私有地址）

子网划分：

  • 将主机号进一步划分为子网号和主机号
  • 子网掩码：网络号+子网号为1，主机号为0
  • 如255.255.255.0（/24）
  • 提高地址利用率，减少广播域

CIDR（无类别域间路由）：

  • 取消分类地址，使用前缀长度表示
  • 如192.168.1.0/24
  • 支持可变长子网掩码（VLSM）
  • 路由聚合（超网），减少路由表规模

域名系统（DNS）：

  • 将域名（如www.example.com）映射为IP地址
  • 分布式层次数据库
  • 递归查询和迭代查询
  • 缓存机制提高效率

端口号

端口号的作用：

  • 标识主机上的进程
  • 16位整数，范围0-65535
  • IP地址+端口号唯一标识一个通信端点（套接字）
  • 源端口+目的端口+源IP+目的IP+协议 唯一标识一个连接

知名端口（Well-known Ports）：

  • 0-1023：由IANA分配，需要特权才能绑定
  • 20/21：FTP（数据/控制）
  • 22：SSH
  • 23：Telnet
  • 25：SMTP
  • 53：DNS
  • 80：HTTP
  • 110：POP3
  • 143：IMAP
  • 443：HTTPS

注册端口和动态端口：

  • 1024-49151：注册端口，用户进程可使用
  • 49152-65535：动态/私有端口，客户端临时端口
  • 客户端通常使用临时端口，服务器使用知名端口

标准化过程

互联网标准化组织：

  • IAB（互联网体系结构委员会）：监督互联网标准
  • IETF（互联网工程任务组）：开发协议标准
  • IRTF（互联网研究任务组）：长期研究
  • IANA（互联网号码分配当局）：分配号码（端口、协议号等）

RFC（Request for Comments）：

  • 互联网标准的文档形式
  • 所有协议都有对应的RFC文档
  • RFC编号唯一，不可修改（更新用新RFC）
  • 如RFC 791（IP）、RFC 793（TCP）、RFC 768（UDP）
  • 状态：提案标准、草案标准、互联网标准

第2章 链路层

链路层的作用

链路层的功能：

  • 为网络层提供服务
  • 将IP数据报封装成帧，通过物理网络传输
  • 物理寻址（MAC地址）
  • 帧同步、差错检测、流量控制
  • 不同的物理网络有不同的链路层协议

常见链路层协议：

  • 以太网（Ethernet）：最常见的局域网技术
  • WiFi（802.11）：无线局域网
  • PPP（点对点协议）：拨号连接
  • SLIP（串行线路IP）：早期串行连接
  • 令牌环（Token Ring）：已淘汰
  • FDDI：光纤分布式数据接口，已淘汰

以太网

以太网帧格式：

  • 目的MAC地址（6字节）
  • 源MAC地址（6字节）
  • 类型/长度（2字节）：0x0800=IP，0x0806=ARP，0x86DD=IPv6
  • 数据（46-1500字节）
  • FCS（帧校验序列，4字节）：CRC校验

MAC地址：

  • 48位物理地址，烧录在网卡中
  • 前24位：OUI（组织唯一标识符），厂商标识
  • 后24位：厂商分配的序列号
  • 表示为十六进制，如00:1A:2B:3C:4D:5E
  • 广播地址：FF:FF:FF:FF:FF:FF
  • MAC地址在链路层使用，IP地址在网络层使用

以太网的特点：

  • 广播信道：所有主机共享同一介质
  • CSMA/CD（载波监听多路访问/冲突检测）：早期半双工以太网
  • 现代以太网全双工，交换机隔离冲突域
  • MTU（最大传输单元）：1500字节
  • 速率：10Mbps、100Mbps、1Gbps、10Gbps、40Gbps、100Gbps

环回接口

环回地址：

  • 127.0.0.1（通常是localhost）
  • 环回接口（lo）：虚拟网络接口
  • 发送到环回地址的数据不会出现在网络上
  • 用于本机进程间通信和测试

环回接口的处理：

  • 发送到环回地址的IP数据报被复制到输入队列
  • 相当于本机既是发送方又是接收方
  • 可以用环回地址测试网络程序（客户端和服务器在同一台机器）

最大传输单元MTU

MTU的概念：

  • 链路层一次能传输的最大数据长度
  • 以太网MTU：1500字节
  • PPP MTU：通常296或1500
  • 不同网络的MTU可能不同

路径MTU：

  • 从源到目的路径上最小的MTU
  • 如果IP数据报大于路径MTU，需要分片
  • 路径MTU发现（PMTU Discovery）：确定路径MTU
  • 设置DF位（不分片），如果需要分片则返回ICMP不可达

第3章 IP：网际协议

IP首部

IP数据报格式：

  • 版本（4位）：IPv4=4
  • 首部长度（4位）：以4字节为单位，通常5（20字节）
  • 服务类型（TOS，8位）：优先级、延迟、吞吐量、可靠性
  • 总长度（16位）：整个数据报长度（首部+数据），最大65535
  • 标识（16位）：唯一标识数据报，用于分片重组
  • 标志（3位）：保留、DF（不分片）、MF（更多分片）
  • 片偏移（13位）：分片在原始数据报中的位置，以8字节为单位
  • 生存时间（TTL，8位）：经过路由器减1，为0时丢弃
  • 协议（8位）：上层协议，1=ICMP，6=TCP，17=UDP
  • 首部校验和（16位）：只校验首部
  • 源IP地址（32位）
  • 目的IP地址（32位）
  • 选项（可选，最多40字节）
  • 数据

IP首部的特点：

  • 最小20字节，最大60字节
  • 32位对齐
  • 网络字节序（大端）
  • TTL防止数据报无限循环
  • 首部校验和每跳都要重新计算（因为TTL变化）

IP路由选择

IP路由的基本原理：

  • 每个主机和路由器都有路由表
  • 路由表条目：目的网络、下一跳、接口、度量
  • 路由查找：最长前缀匹配
  • 默认路由：0.0.0.0/0，匹配所有未明确路由的目的

路由过程：

  1. 搜索路由表，寻找与目的IP完全匹配的主机路由
  2. 搜索匹配目的网络号的网络路由
  3. 搜索默认路由
  4. 如果都没找到，返回”主机不可达”或”网络不可达”ICMP

路由表类型：

  • 直连路由：直接连接的网络
  • 静态路由：手动配置
  • 动态路由：通过路由协议学习（RIP、OSPF、BGP等）
  • 默认路由

IP路由的特点：

  • 逐跳路由：每个路由器只决定下一跳
  • 源路由选项：源主机指定完整路径（很少使用）
  • 路由器不关心数据内容，只根据目的IP转发

子网寻址

子网划分的动机：

  • 分类地址浪费严重（B类网络可容纳65534主机，但很多网络用不完）
  • 提高地址利用率
  • 减少广播域，提高网络性能
  • 便于管理和安全隔离

子网掩码：

  • 32位，网络号和子网号为1，主机号为0
  • 点分十进制表示（如255.255.255.0）或前缀长度（如/24）
  • 与IP地址按位与得到网络地址
  • 主机号全0：网络地址；全1：广播地址

子网划分示例：

  • B类网络172.16.0.0/16，借8位作为子网号
  • 子网掩码255.255.255.0（/24）
  • 可划分256个子网（实际254个，全0全1保留）
  • 每个子网可容纳254台主机
  • 子网172.16.1.0、172.16.2.0等

特殊IP地址

地址类型 网络号 主机号 用途
本网络本主机 0 0 启动时使用，之后不用
本网络特定主机 0 主机号 本网络内的主机
广播地址 网络号 全1 向网络内所有主机广播
环回地址 127 任意 本机测试
私有地址 10/8、172.16/12、192.168/16 - 内部网络，不路由到公网
链路本地地址 169.254/16 - 自动配置（DHCP失败时）
组播地址 224/4 - 组播通信
保留地址 240/4 - 保留未用

第4章 ARP：地址解析协议

ARP的作用

ARP的功能：

  • 将IP地址解析为MAC地址
  • 网络层使用IP地址，链路层使用MAC地址
  • 发送数据报时需要知道下一跳的MAC地址
  • ARP提供IP到MAC的动态映射

ARP的工作过程：

  1. 主机A要向主机B发送IP数据报
  2. 主机A先查ARP缓存，看是否有B的IP对应的MAC
  3. 如果没有，A发送ARP请求（广播）：”谁有IP地址B？请告诉A”
  4. 所有主机收到请求，只有B识别自己的IP，发送ARP应答（单播）：”我是B，我的MAC是…”
  5. A收到应答，更新ARP缓存
  6. A使用B的MAC地址封装帧发送数据

ARP缓存：

  • 存储IP到MAC的映射
  • 动态条目有超时时间（通常20分钟）
  • 静态条目永久有效
  • 减少ARP请求广播，提高效率

ARP报文格式

ARP报文：

  • 硬件类型（16位）：1=以太网
  • 协议类型（16位）：0x0800=IP
  • 硬件地址长度（8位）：6（MAC地址）
  • 协议地址长度（8位）：4（IP地址）
  • 操作码（16位）：1=请求，2=应答
  • 发送端MAC地址（6字节）
  • 发送端IP地址（4字节）
  • 目标MAC地址（6字节，请求时全0）
  • 目标IP地址（4字节）

ARP报文封装在以太网帧中：

  • 类型字段0x0806
  • ARP请求：目的MAC为广播地址FF:FF:FF:FF:FF:FF
  • ARP应答：目的MAC为请求者的MAC

免费ARP和ARP代理

免费ARP（Gratuitous ARP）：

  • 主机启动时发送ARP请求查询自己的IP地址
  • 作用：
    • 检测IP地址冲突（如果有应答说明IP已被使用）
    • 更新其他主机的ARP缓存（MAC地址可能变化）
    • 路由器使用免费ARP更新主机的默认网关映射

ARP代理（Proxy ARP）：

  • 路由器代替目标主机响应ARP请求
  • 用于不同物理网络但同一IP网络的情况
  • 主机认为目标在同一网络，发送ARP请求
  • 路由器知道目标在其他网络，用自己的MAC应答
  • 主机将数据发送给路由器，路由器转发
  • 现在已被子网划分取代，很少使用

RARP：逆地址解析协议

RARP的作用：

  • 将MAC地址解析为IP地址
  • 用于无盘工作站（启动时不知道自己的IP）
  • 反向ARP：广播RARP请求（包含自己的MAC），RARP服务器应答IP
  • 已被BOOTP和DHCP取代

BOOTP和DHCP：

  • BOOTP（引导协议）：比RARP更强大，可提供更多配置信息
  • DHCP（动态主机配置协议）：BOOTP的扩展，动态分配IP地址
  • DHCP是目前最常用的主机配置协议
  • 提供：IP地址、子网掩码、默认网关、DNS服务器、域名等

第5章 ICMP：网际控制报文协议

ICMP的作用

ICMP的功能：

  • IP协议的辅助协议，传递差错和控制信息
  • 封装在IP数据报中传输（协议号1）
  • 不保证可靠传输
  • 用于报告错误、查询信息、诊断问题

ICMP报文类型：

  • 差错报告报文：
    • 目的不可达（3）
    • 源抑制（4）
    • 重定向（5）
    • 超时（11）
    • 参数问题（12）
  • 查询报文：
    • 回显请求/应答（8/0）：Ping
    • 时间戳请求/应答（13/14）
    • 地址掩码请求/应答（17/18）
    • 路由器通告/请求（9/10）

ICMP报文格式

ICMP通用格式：

  • 类型（8位）：报文类型
  • 代码（8位）：进一步细分类型
  • 校验和（16位）：整个ICMP报文
  • 内容（取决于类型）

常见ICMP报文：

  • 回显请求/应答：标识符、序列号、数据
  • 目的不可达：未用（4字节）+ 原始IP首部+前8字节数据
  • 超时：同上
  • 重定向：网关IP地址 + 原始IP首部+前8字节数据

ICMP差错报文

目的不可达：

  • 类型3，代码0-15
  • 常见代码：
    • 0：网络不可达
    • 1：主机不可达
    • 2：协议不可达
    • 3：端口不可达
    • 4：需要分片但设置了DF位
    • 5：源路由失败
  • 路由器或主机发送

超时：

  • 类型11
  • 代码0：传输期间TTL为0（Traceroute使用）
  • 代码1：分片重组超时
  • 路由器发送TTL超时，目的主机发送重组超时

重定向：

  • 类型5
  • 代码0-3：网络重定向、主机重定向、服务类型和网络重定向、服务类型和主机重定向
  • 路由器发送，告诉主机有更好的路由
  • 主机更新路由表

源抑制：

  • 类型4
  • 路由器拥塞时发送，告诉源主机降低发送速率
  • 现代网络很少使用（TCP有自己的拥塞控制）

ICMP差错报文的规则：

  • 不对ICMP差错报文生成ICMP差错报文（防止无限循环）
  • 对目的地址为广播/多播的IP数据报不生成ICMP差错
  • 对链路层广播的数据报不生成ICMP差错
  • 对不是第一个分片的分片不生成ICMP差错
  • 对源地址不是单播的不生成ICMP差错

第6章 Ping程序

Ping的原理

Ping的作用：

  • 测试主机是否可达
  • 测量往返时间（RTT）
  • 测试网络连通性和丢包率
  • 网络诊断最常用的工具

Ping的工作原理：

  • 使用ICMP回显请求（类型8）和回显应答（类型0）
  • 发送ICMP回显请求，包含标识符和序列号
  • 目标主机返回ICMP回显应答
  • 计算发送和接收的时间差得到RTT
  • 统计丢包率和RTT统计

Ping的输出示例：

Ping的实现细节

IP记录路由选项：

  • Ping可以使用IP记录路由选项（RR）
  • 记录数据报经过的路由器IP
  • 选项空间有限（最多9个路由器地址）
  • 现代网络很多路由器不处理记录路由选项

IP时间戳选项：

  • 记录经过路由器的时间戳
  • 也受选项空间限制
  • 很少使用

Ping的常见选项：

  • -c count：发送指定数量的请求
  • -i interval：发送间隔
  • -s size：数据大小
  • -t ttl：设置TTL
  • -W timeout：等待应答超时
  • -R：记录路由
  • -f：洪水Ping（快速发送，压力测试）

Ping的注意事项

Ping不可达的原因：

  • 主机宕机或关机
  • 网络中断
  • 防火墙禁止ICMP
  • 主机配置不响应ICMP回显
  • 路由不可达
  • Ping不通不代表服务不可用（可能只是禁了ICMP）

Ping的安全问题：

  • Ping洪水攻击（Ping of Death、Smurf攻击）
  • 很多网络限制ICMP速率
  • 防火墙可能丢弃ICMP
  • 现代网络中Ping的诊断价值下降

第7章 Traceroute程序

Traceroute的原理

Traceroute的作用：

  • 追踪IP数据报从源到目的经过的路由
  • 显示每一跳的路由器IP和RTT
  • 诊断网络路由问题
  • 比Ping更强大的网络诊断工具

Traceroute的工作原理（Unix实现）：

  • 使用UDP数据报和ICMP超时报文
  • 发送TTL=1的UDP数据报到目的的高端口
  • 第一个路由器收到后TTL减1为0，返回ICMP超时（包含路由器IP）
  • 发送TTL=2的UDP数据报，第二个路由器返回超时
  • 逐步增加TTL，直到到达目的主机
  • 目的主机收到UDP数据报，端口不可达，返回ICMP端口不可达
  • 收到端口不可达表示到达目的，追踪结束

Windows的tracert：

  • 使用ICMP回显请求而不是UDP
  • 原理相同：逐步增加TTL，利用ICMP超时
  • 目的主机返回ICMP回显应答表示到达

Traceroute的输出

输出示例：

输出解释：

  • 每行：跳数、路由器IP/主机名、三个RTT（发送三个探测包）
      • *：超时（路由器不返回ICMP超时，或丢包）
  • 最后一行是目的主机

Traceroute的注意事项

Traceroute的限制：

  • 不对称路由：去程和回程可能不同，RTT反映的是往返
  • 路由器可能不返回ICMP超时（显示* * *）
  • 负载均衡：多个探测包可能走不同路径
  • 防火墙可能拦截UDP或ICMP
  • 不反映实际性能（路由器可能优先处理数据而不是ICMP）

Traceroute的高级用法：

  • -I：使用ICMP而不是UDP
  • -T：使用TCP SYN
  • -p port：指定目的端口
  • -q nqueries：每跳发送的探测包数量
  • -m max_ttl：最大跳数
  • -n：不解析主机名（更快）
  • 现代工具：mtr（My Traceroute，结合Ping和Traceroute）

第8章 IP选路

路由表

路由表的结构：

  • 目的网络地址
  • 子网掩码
  • 下一跳地址（网关）
  • 输出接口
  • 度量（Metric）
  • 标志（U=可用，G=网关，H=主机路由，D=动态，M=已修改）

路由查找算法：

  1. 搜索匹配目的IP的主机路由（完整IP匹配）
  2. 搜索匹配目的网络的网络路由
  3. 搜索默认路由
  4. 都没找到则报错

路由表示例：

路由选择原则

最长前缀匹配：

  • 路由表可能有多个条目匹配目的IP
  • 选择前缀最长（最具体）的条目
  • 如目的IP 192.168.1.5，匹配192.168.1.0/24而不是192.168.0.0/16
  • 默认路由0.0.0.0/0是最短前缀，最后匹配

路由决策过程：

  1. 搜索路由表
  2. 确定下一跳和输出接口
  3. 如果目的在直连网络，下一跳就是目的本身
  4. 如果目的在其他网络，发送给下一跳路由器
  5. 封装帧，下一跳的MAC地址（需要ARP解析）

静态路由和动态路由

静态路由：

  • 手动配置路由表
  • 简单、可控、无额外开销
  • 不适应网络拓扑变化
  • 适用于小型网络或稳定网络
  • route/ip route命令配置

动态路由：

  • 通过路由协议自动学习和更新路由
  • 适应网络拓扑变化
  • 有额外开销（路由协议报文、CPU、带宽）
  • 适用于大型网络
  • 内部网关协议（IGP）：RIP、OSPF、IS-IS
  • 外部网关协议（EGP）：BGP

路由协议分类：

  • 距离矢量协议：RIP（跳数度量，最大15跳）
  • 链路状态协议：OSPF（SPF算法，度量为带宽/延迟）
  • 路径矢量协议：BGP（AS路径，互联网域间路由）

第9章 动态选路协议

RIP：路由信息协议

RIP的特点：

  • 距离矢量协议
  • 度量：跳数（最大15跳，16表示不可达）
  • 每30秒广播/组播路由表更新
  • 触发更新：拓扑变化时立即发送
  • 适用于小型网络
  • RIP v1：有类路由，广播更新
  • RIP v2：无类路由，支持认证，组播更新（224.0.0.9）

RIP的问题：

  • 跳数限制（最大15跳）
  • 收敛慢（计数到无穷问题）
  • 不考虑带宽、延迟等因素
  • 定期更新浪费带宽
  • 不适合大型网络

RIP的防环机制：

  • 水平分割：不从收到路由的接口发回该路由
  • 毒性逆转：将从某接口收到的路由度量设为16发回
  • 触发更新
  • 抑制计时

OSPF：开放最短路径优先

OSPF的特点：

  • 链路状态协议
  • 度量：代价（Cost，通常基于带宽）
  • 使用SPF（最短路径优先）算法（Dijkstra算法）
  • 支持区域划分（Area），减少路由表规模
  • 组播更新（224.0.0.5、224.0.0.6）
  • 支持认证
  • 收敛快，适用于大型网络

OSPF的基本概念：

  • 链路状态通告（LSA）：描述路由器的链路状态
  • 链路状态数据库（LSDB）：所有LSA的集合
  • 区域（Area）：逻辑分组，Area 0是骨干区域
  • 路由器类型：内部路由器、骨干路由器、ABR（区域边界路由器）、ASBR（自治系统边界路由器）
  • DR/BDR：指定路由器/备份指定路由器（广播网络中减少LSA交换）

OSPF的优势：

  • 无跳数限制
  • 收敛快
  • 支持VLSM和CIDR
  • 度量考虑带宽
  • 支持区域划分，可扩展
  • 是目前企业网最常用的内部网关协议

BGP：边界网关协议

BGP的特点：

  • 路径矢量协议
  • 用于自治系统（AS）之间的路由（域间路由）
  • 度量：AS路径（经过的AS号列表）
  • 基于TCP（端口179）
  • 策略丰富，可基于多种属性选择路由
  • 是互联网的核心路由协议

BGP的基本概念：

  • 自治系统（AS）：同一管理域的网络集合，有唯一AS号
  • eBGP：不同AS之间的BGP
  • iBGP：同一AS内部的BGP
  • BGP属性：AS路径、下一跳、本地优先级、MED、团体等
  • 路由选择基于策略，不一定是最短路径

第10章 UDP：用户数据报协议

UDP首部

UDP数据报格式：

  • 源端口（16位）
  • 目的端口（16位）
  • 长度（16位）：UDP首部+数据，最小8
  • 校验和（16位）：可选，覆盖UDP首部+数据+伪首部
  • 数据

UDP的特点：

  • 无连接：发送数据前不需要建立连接
  • 不可靠：不保证交付、不保证顺序、不重复
  • 没有拥塞控制
  • 首部开销小（8字节）
  • 支持广播和组播
  • 适用于实时应用（视频、语音、游戏、DNS）

UDP校验和

UDP校验和的计算：

  • 覆盖：伪首部 + UDP首部 + UDP数据
  • 伪首部：源IP、目的IP、0、协议（17）、UDP长度
  • 伪首部不传输，只用于校验和计算
  • 校验和为0表示不计算校验和（IPv4可选，IPv6强制）
  • 如果计算结果为0，存储为全1（避免与”不计算”混淆）

UDP校验和的意义：

  • 检测数据在传输中是否损坏
  • IP首部校验和只校验IP首部，不校验数据
  • UDP校验和提供端到端的数据完整性校验
  • 虽然UDP不可靠，但校验和能检测损坏

UDP的应用

常见UDP应用：

  • DNS（域名系统）：53端口
  • DHCP（动态主机配置协议）：67/68端口
  • TFTP（简单文件传输协议）：69端口
  • SNMP（简单网络管理协议）：161/162端口
  • NTP（网络时间协议）：123端口
  • RIP（路由信息协议）：520端口
  • VoIP、视频流、在线游戏

UDP vs TCP的选择：

  • 需要可靠传输：TCP
  • 需要低延迟、可容忍少量丢包：UDP
  • 需要广播/组播：UDP
  • 简单请求-响应：UDP（如DNS）
  • 大量数据传输：TCP
  • 实时应用：UDP（或QUIC等基于UDP的可靠协议）

第11章 TCP：传输控制协议

TCP的特点

TCP的核心特性：

  • 面向连接：通信前必须建立连接（三次握手）
  • 可靠传输：确认、重传、序号、校验和
  • 全双工：同一连接可同时双向传输
  • 字节流：不保留消息边界，应用层需要自己处理
  • 流量控制：滑动窗口，防止发送方淹没接收方
  • 拥塞控制：防止发送方淹没网络
  • 点对点：一对一通信（不支持广播/组播）

TCP vs UDP：

特性 TCP UDP
连接 面向连接 无连接
可靠性 可靠 不可靠
顺序 保证顺序 不保证
流量控制 有 无
拥塞控制 有 无
首部开销 20-60字节 8字节
广播/组播 不支持 支持
适用场景 文件传输、Web、邮件 实时应用、DNS、游戏

TCP首部

TCP段格式：

  • 源端口（16位）
  • 目的端口（16位）
  • 序号（32位）：本报文段数据的第一个字节的序号
  • 确认号（32位）：期望收到的下一个字节的序号，确认之前所有字节
  • 首部长度（4位）：以4字节为单位，通常5（20字节）
  • 保留（6位）
  • 标志位（6位）：
    • URG：紧急指针有效
    • ACK：确认号有效
    • PSH：推送功能
    • RST：复位连接
    • SYN：同步序号（建立连接）
    • FIN：发送完成（关闭连接）
  • 窗口大小（16位）：接收窗口，流量控制
  • 校验和（16位）：TCP首部+数据+伪首部
  • 紧急指针（16位）：URG有效时，紧急数据的末尾偏移
  • 选项（可选，最多40字节）：MSS、窗口扩大、时间戳、SACK等
  • 数据

TCP序号和确认号：

  • 序号是字节流的编号，不是段的编号
  • 建立连接时双方各自选择初始序号（ISN）
  • 序号随数据字节递增
  • 确认号是期望收到的下一个字节序号
  • 累计确认：确认号N表示N之前的所有字节都已收到

TCP选项：

  • MSS（最大段大小）：TCP段最大数据长度，通常MTU-40
  • 窗口扩大选项：窗口大小从16位扩大到30位
  • 时间戳选项：计算RTT、防止序号回绕
  • SACK（选择性确认）：确认不连续的数据块，提高重传效率

第12章 TCP连接的建立与终止

三次握手

连接建立过程：

  1. 客户端发送SYN（SYN=1，ACK=0），序号=ISN(c)
  2. 服务器回复SYN+ACK（SYN=1，ACK=1），序号=ISN(s)，确认号=ISN(c)+1
  3. 客户端发送ACK（ACK=1），序号=ISN(c)+1，确认号=ISN(s)+1
  • 连接建立，双方可以开始传输数据

为什么是三次握手：

  • 两次握手不够：无法确认客户端的接收能力，可能导致服务器资源浪费（旧的SYN请求）
  • 三次握手可以确认双方的发送和接收能力
  • 同步双方的初始序号
  • 防止已失效的连接请求突然又传到服务器

SYN洪水攻击：

  • 攻击者发送大量SYN请求，但不完成第三次握手
  • 服务器维护半连接队列，资源耗尽
  • 防御：SYN Cookie、半连接队列限制、SYN速率限制

四次挥手

连接终止过程：

  1. 客户端发送FIN（FIN=1），表示数据发送完成
  2. 服务器回复ACK，确认FIN
  3. 服务器发送FIN，表示服务器数据也发送完成
  4. 客户端回复ACK，确认服务器的FIN
  • 连接完全关闭

为什么是四次挥手：

  • TCP全双工，两个方向需要分别关闭
  • FIN只能关闭一个方向
  • 收到FIN后可能还有数据要发送，所以ACK和FIN分开
  • 半关闭：一方关闭发送，但仍可接收

TIME_WAIT状态

TIME_WAIT状态：

  • 主动关闭的一方（发送最后一个ACK的一方）进入TIME_WAIT
  • 持续2MSL（最大报文段生存时间，通常2分钟）
  • 之后进入CLOSED状态

TIME_WAIT的作用：

  1. 可靠地实现TCP全双工连接的终止
    • 最后一个ACK可能丢失，对方会重发FIN
    • TIME_WAIT期间可以重发ACK
  2. 允许老的重复分节在网络中消逝
    • 防止旧连接的报文被新连接（相同四元组）错误接收

TIME_WAIT的问题：

  • 大量短连接导致很多TIME_WAIT状态
  • 占用系统资源（端口、内存）
  • 优化：调整net.ipv4.tcp_tw_reuse、tcp_tw_recycle、tcp_fin_timeout
  • 注意：tcp_tw_recycle在NAT环境下有问题，已废弃

TCP状态机

TCP状态：

  • CLOSED：关闭
  • LISTEN：监听（服务器）
  • SYN_SENT：已发送SYN（客户端）
  • SYN_RCVD：已收到SYN，发送SYN+ACK（服务器）
  • ESTABLISHED：连接已建立
  • FIN_WAIT_1：已发送FIN
  • FIN_WAIT_2：已收到FIN的ACK
  • CLOSE_WAIT：已收到FIN，等待应用关闭
  • CLOSING：双方同时关闭
  • LAST_ACK：已发送FIN，等待最后ACK
  • TIME_WAIT：主动关闭后的等待状态

状态转换：

  • 客户端：CLOSED → SYN_SENT → ESTABLISHED → FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED
  • 服务器：CLOSED → LISTEN → SYN_RCVD → ESTABLISHED → CLOSE_WAIT → LAST_ACK → CLOSED

第13章 TCP的交互数据流

交互式输入

交互式TCP：

  • 如Telnet、SSH、Rlogin
  • 每次按键产生一个数据段（1字节数据+20字节首部=41字节）
  • 效率低（首部开销大）

延迟确认（Delayed ACK）：

  • 收到数据后不立即发送ACK
  • 等待一段时间（通常200ms），看是否有数据要一起发送（捎带确认）
  • 如果有数据发送，ACK捎带在数据段中
  • 如果超时没有数据，单独发送ACK
  • 减少ACK数量，提高效率

Nagle算法：

  • 解决小数据段问题（糊涂窗口综合征的发送方问题）
  • 规则：
    • 如果发送窗口≥MSS且数据≥MSS，立即发送
    • 如果没有未确认的数据，立即发送
    • 否则，缓存数据，直到收到ACK或数据达到MSS
  • 减少小数据段数量
  • 交互式应用（如X Window）可能需要禁用Nagle（TCP_NODELAY选项）

糊涂窗口综合征

糊涂窗口综合征（Silly Window Syndrome, SWS）：

  • 接收方通告很小的窗口，发送方发送很小的数据段
  • 导致大量小数据段，效率极低
  • 可能由发送方或接收方引起

接收方避免SWS：

  • 不通告小窗口
  • 直到窗口可以增加到MSS或缓冲区一半大小才通告
  • Clark算法：即使有数据可读，也不通告小窗口

发送方避免SWS：

  • Nagle算法
  • 不发送小于MSS的数据段，除非：
    • 没有未确认的数据
    • 或可以立即发送全大小段
    • 或数据被推送（PSH）

第14章 TCP的成块数据流

流量控制

滑动窗口：

  • TCP通过窗口大小进行流量控制
  • 接收方在ACK中通告窗口大小（接收缓冲区可用空间）
  • 发送方发送的数据不能超过窗口大小
  • 窗口随数据发送和确认而滑动

窗口管理：

  • 发送窗口 = min(接收窗口, 拥塞窗口)
  • 接收窗口由接收方控制（流量控制）
  • 拥塞窗口由发送方控制（拥塞控制）
  • 零窗口探测：接收方窗口为0时，发送方定期发送探测段

成块数据流的特点：

  • 如FTP文件传输
  • 发送方尽量发送满大小段（MSS）
  • 接收方批量确认（累积确认）
  • 效率高，吞吐量接近链路带宽

慢启动和拥塞避免

拥塞控制的必要性：

  • 网络容量有限，如果发送方发送过快，路由器会丢包
  • 丢包导致重传，进一步加剧拥塞
  • 需要拥塞控制机制，使发送方适应网络容量

慢启动（Slow Start）：

  • 连接建立或超时后，拥塞窗口（cwnd）初始为1个MSS
  • 每收到一个ACK，cwnd增加1个MSS
  • 实际是指数增长（每轮RTT翻倍）
  • “慢启动”指初始速度慢，但增长很快
  • 直到达到慢启动阈值（ssthresh）或检测到丢包

拥塞避免（Congestion Avoidance）：

  • cwnd ≥ ssthresh时进入拥塞避免
  • 每轮RTT，cwnd增加1个MSS（线性增长）
  • 加法增加，乘法减小（AIMD）
  • 检测到丢包时，ssthresh = cwnd/2，cwnd重置

拥塞检测：

  • 超时重传：严重拥塞，cwnd=1，ssthresh=cwnd/2，重新慢启动
  • 三个重复ACK：轻度拥塞，ssthresh=cwnd/2，cwnd=ssthresh，进入拥塞避免（快速恢复）

快速重传和快速恢复

快速重传（Fast Retransmit）：

  • 收到三个重复ACK时，立即重传丢失的段
  • 不需要等待重传计时器超时
  • 大大减少重传延迟

快速恢复（Fast Recovery）：

  • 快速重传后，不进入慢启动
  • ssthresh = cwnd/2
  • cwnd = ssthresh + 3*MSS（三个重复ACK表示有3个段已离开网络）
  • 每收到一个重复ACK，cwnd增加1个MSS
  • 收到新数据的ACK时，cwnd = ssthresh，进入拥塞避免
  • 快速恢复避免了不必要的慢启动，提高吞吐量

TCP吞吐量

TCP吞吐量公式：

  • 吞吐量 ≈ MSS / (RTT × sqrt(p))
  • p = 丢包率
  • 吞吐量与MSS成正比，与RTT和sqrt(丢包率)成反比
  • 高带宽长延迟网络（长肥网络）中，TCP性能受窗口大小限制

长肥网络的问题：

  • 带宽×延迟乘积大，需要大窗口
  • 窗口扩大选项将窗口从16位扩大到30位
  • 丢包对吞吐量影响大（高带宽下少量丢包导致吞吐量骤降）
  • 需要新的拥塞控制算法（如BBR、CUBIC）

第15章 TCP重传

重传机制

TCP可靠性的基础：

  • 每个数据段有序号
  • 接收方累计确认
  • 发送方维护未确认段的重传队列
  • 超时未收到确认则重传

重传计时器：

  • 每个未确认段都有重传计时器
  • 计时器超时则重传该段
  • 重传后重置计时器（指数退避）

RTT测量

RTT估计：

  • TCP需要测量往返时间（RTT）来设置重传超时
  • 原始方法：测量每个段的RTT，取加权平均
  • Karn算法：重传的段不用于RTT测量（因为不知道是原始段还是重传段的ACK）
  • 重传时超时时间指数退避

RFC 6298的RTT估计：

  • SRTT（平滑RTT）：SRTT = (1-α)×SRTT + α×RTT，α=1/8
  • RTTVAR（RTT偏差）：RTTVAR = (1-β)×RTTVAR + β×|SRTT-RTT|，β=1/4
  • RTO（重传超时）：RTO = SRTT + max(G, 4×RTTVAR)
  • G为时钟粒度
  • 初始RTO=1秒，最小RTO=1秒（RFC建议），最大RTO=60秒

快速重传

快速重传的触发：

  • 收到三个重复ACK（共四个相同的ACK）
  • 立即重传丢失的段
  • 不等待重传计时器超时

快速重传的优势：

  • 减少重传延迟（通常一个RTT内，而不是等待RTO）
  • 提高吞吐量
  • 现代TCP中大部分重传是快速重传

SACK（选择性确认）：

  • 传统TCP只能确认连续的数据（累计确认）
  • SACK可以确认不连续的数据块
  • 接收方告诉发送方哪些块已收到，哪些丢失
  • 发送方只重传真正丢失的块
  • 提高多包丢失时的重传效率
  • SACK是TCP选项，需要双方都支持

第16章 TCP定时器

连接建立定时器

连接建立超时：

  • SYN发送后启动定时器
  • 超时未收到SYN+ACK则重传SYN
  • 重传次数有限（通常5-6次）
  • 总超时时间约75秒
  • SYN洪水攻击利用这个特性

重传定时器

重传定时器：

  • 每个未确认段都有
  • 超时则重传
  • RTO基于RTT估计
  • 指数退避：每次重传RTO翻倍

坚持定时器

坚持定时器（Persist Timer）：

  • 接收方通告零窗口后，发送方启动坚持定时器
  • 定时器超时发送零窗口探测段（1字节数据）
  • 探测接收方窗口是否已打开
  • 防止窗口更新丢失导致死锁
  • 探测间隔指数退避（5s, 10s, 20s…最大60s）

保活定时器

保活定时器（Keepalive Timer）：

  • 检测空闲连接的对端是否仍然存活
  • 默认关闭（应用层可启用）
  • 连接空闲2小时后发送保活探测段
  • 如果无响应，每75秒发送一次，共9次
  • 仍无响应则认为对端已关闭，终止连接
  • 保活不是TCP标准的一部分，是常见实现
  • 争议：浪费带宽、可能在临时断网时误杀连接

2MSL定时器

2MSL定时器：

  • TIME_WAIT状态持续2MSL
  • MSL（最大报文段生存时间）：报文段在网络中最大存活时间
  • RFC建议MSL=2分钟，实际实现通常30秒-2分钟
  • 2MSL确保：
    • 最后一个ACK可靠到达（丢失可重传）
    • 旧连接的报文在网络中消逝

《TCP/IP详解 卷1：协议》是TCP/IP协议领域的圣经级经典，由W. Richard Stevens编写，第二版由Kevin R. Fall更新。本书深入剖析TCP/IP协议族的每个协议，配合大量实际抓包案例，是理解网络协议本质的必读之作。

学习建议：

  • 本书是网络协议的经典，需要配合抓包工具（Wireshark/tcpdump）学习
  • 每章都有大量实际抓包案例，一定要动手抓包分析

  • 配合《计算机网络：自顶向下方法》学习效果更好
  • 学习Wireshark的使用，能分析实际网络流量
  • 本书第一版基于4.4BSD，第二版更新了部分内容，但核心协议不变
  • TCP/IP协议是互联网的基础，理解协议本质对网络编程、系统运维、安全都非常重要

这本书是每个网络工程师、系统管理员、后端开发者必读的经典，深入理解TCP/IP协议是理解互联网运作原理的关键。
