现代操作系统

现代操作系统（第四版）

作者：Andrew S. Tanenbaum, Herbert Bos
全书共13章，626页，系统讲解操作系统的基本原理和设计思想，涵盖进程、内存、文件、I/O、死锁、虚拟化、多处理机、安全等核心主题，并结合UNIX/Linux/Android和Windows实例分析。

第1章 引论

1.1 什么是操作系统

操作系统定义：

  • 操作系统是管理计算机硬件与软件资源的系统软件
  • 为应用程序提供运行环境和抽象接口
  • 是硬件与用户之间的中介

操作系统的两个目标：

  1. 向用户程序提供抽象：隐藏硬件复杂性，提供简洁易用的接口（如文件抽象替代磁盘操作）
  2. 管理硬件资源：在相互竞争的程序之间有序地控制处理器、内存和I/O设备的分配

操作系统的扩展机器观点：

  • 操作系统将丑陋的硬件转换为美观、易用的抽象
  • 如：文件抽象（替代磁盘扇区操作）、进程抽象（替代CPU直接操作）、虚拟内存（替代物理内存管理）

操作系统的资源管理观点：

  • 操作系统是资源管理器，管理CPU、内存、I/O设备等
  • 资源复用方式：
    • 时间复用：多个程序轮流使用CPU（进程调度）
    • 空间复用：多个程序共享内存（内存管理）

1.2 操作系统历史

第一代（1945-1955）：真空管和穿孔卡片

  • 无操作系统，直接用机器语言编程
  • ENIAC等早期计算机
  • 人工操作，效率极低

第二代（1955-1965）：晶体管和批处理系统

  • 晶体管替代真空管
  • 批处理系统：将作业批量读入磁带，依次处理
  • 监控程序（Monitor）：自动加载和运行作业
  • FMS（Fortran监控系统）、IBSYS

第三代（1965-1980）：集成电路和多道程序设计

  • 集成电路（IC）替代晶体管
  • 多道程序设计：内存中同时存放多个作业，CPU在它们之间切换，提高利用率
  • 分时系统：多个用户通过终端同时使用计算机（CTSS、Multics、UNIX）
  • IBM System/360：首个系列化计算机，OS/360操作系统
  • 小型机兴起（DEC PDP系列）

第四代（1980-至今）：个人计算机

  • 大规模集成电路（LSI/VLSI）
  • 个人计算机（PC）兴起：IBM PC、Apple Macintosh
  • 操作系统：MS-DOS、Windows、Mac OS、Linux
  • 图形用户界面（GUI）普及
  • 网络和分布式系统发展
  • 移动操作系统：iOS、Android
  • 云计算和虚拟化

1.3 计算机硬件介绍

处理器（CPU）：

  • 取指-译码-执行周期
  • 寄存器：通用寄存器、程序计数器（PC）、堆栈指针（SP）、程序状态字（PSW）
  • 流水线：指令重叠执行，提高吞吐量
  • 超标量：多个执行单元并行执行指令
  • 多核处理器：一个芯片上集成多个CPU核心

存储器层次：

  • 寄存器 → 高速缓存（L1/L2/L3） → 主存（RAM） → 磁盘 → 磁带
  • 速度递减，容量递增，成本递减
  • 局部性原理：时间局部性（最近访问的数据很快会再访问）、空间局部性（相邻地址的数据会被访问）
  • 缓存命中/未命中

磁盘：

  • 磁道、扇区、柱面
  • 寻道时间、旋转延迟、传输时间
  • 固态硬盘（SSD）：无机械部件，更快更可靠，但成本更高

I/O设备：

  • 设备控制器：I/O设备与系统总线之间的接口
  • I/O方式：
    • 程序控制I/O（忙等待）：CPU轮询设备状态
    • 中断驱动I/O：设备完成后发中断通知CPU
    • DMA（直接存储器访问）：DMA控制器直接在设备和内存间传输数据，CPU不参与

总线：

  • 系统总线：连接CPU、内存、I/O控制器
  • PCIe（PCI Express）：现代高速串行总线
  • USB：通用串行总线，连接外部设备

1.4 操作系统大论战

操作系统设计的关键问题：

  • 单体内核 vs 微内核
  • 性能 vs 可维护性
  • 安全性 vs 易用性

操作系统的类型：

  • 大型机操作系统：z/OS
  • 服务器操作系统：Linux、Windows Server
  • 多处理器操作系统
  • 个人计算机操作系统：Windows、macOS、Linux桌面版
  • 手持设备操作系统：Android、iOS
  • 嵌入式操作系统：VxWorks、QNX、FreeRTOS
  • 传感器节点操作系统：TinyOS
  • 实时操作系统（RTOS）

第2章 进程与线程

2.1 进程

进程概念：

  • 进程是程序的一次执行过程，是资源分配和调度的基本单位
  • 进程 = 程序 + 数据 + 进程控制块（PCB）
  • 程序是静态的，进程是动态的

进程的创建：

  • 系统初始化
  • 正在运行的进程调用创建原语（fork/CreateProcess）
  • 用户请求创建新进程
  • 批处理作业的初始化

进程的终止：

  • 正常退出（自愿）
  • 出错退出（自愿）
  • 严重错误（非自愿）
  • 被其他进程杀死（非自愿）

进程的层次结构：

  • UNIX：进程树，init进程是所有进程的祖先
  • Windows：进程间无严格层次关系，句柄可继承

进程状态：

  1. 运行态：正在CPU上执行
  2. 就绪态：可运行，等待CPU调度
  3. 阻塞态：等待某事件发生（如I/O完成）
  • 状态转换：运行→阻塞（等待事件）、运行→就绪（时间片到/高优先级进程）、阻塞→就绪（事件发生）、就绪→运行（调度选中）

进程控制块（PCB）：

  • 进程标识：PID、父进程ID、用户ID
  • 处理器状态：程序计数器、寄存器、PSW
  • 进程调度信息：状态、优先级、调度参数
  • 内存管理信息：页表/段表、内存使用
  • I/O状态信息：打开的文件、设备
  • 会计信息：CPU使用时间、资源使用统计

进程调度队列：

  • 就绪队列：所有就绪进程
  • 等待队列：按等待事件分类（I/O队列、信号队列等）

2.2 线程

线程概念：

  • 线程是CPU调度的最小单位，是进程内的执行单元
  • 一个进程可包含多个线程，共享进程的地址空间和资源
  • 线程有自己的程序计数器、寄存器、堆栈

为什么引入线程：

  • 并行性：一个进程内多个线程可并行执行（多CPU）或并发执行（单CPU）
  • 开销小：创建/销毁/切换线程比进程快（共享地址空间，无需切换页表）
  • 通信方便：线程间共享内存，直接通信
  • 响应性：一个线程阻塞不影响其他线程

线程的实现：

  • 用户级线程：在用户空间实现，内核不知道线程存在
    • 优点：切换快、可自定义调度、不依赖内核支持
    • 缺点：一个线程阻塞则整个进程阻塞、无法利用多CPU
  • 内核级线程：由内核管理和调度
    • 优点：一个线程阻塞不影响其他线程、可利用多CPU
    • 缺点：切换开销大（需陷入内核）
  • 混合实现：用户级线程映射到内核级线程（多对多模型）

POSIX线程（Pthreads）：

  • pthread_create：创建线程
  • pthread_exit：线程退出
  • pthread_join：等待线程结束
  • pthread_yield：让出CPU
  • pthread_mutex_init/lock/unlock：互斥锁
  • pthread_cond_init/wait/signal：条件变量

2.3 进程间通信

进程间通信（IPC）问题：

  • 进程间如何传递信息
  • 如何确保进程间操作不互相干扰（互斥）
  • 如何协调执行顺序（同步）

竞争条件（Race Condition）：

  • 多个进程访问和操作共享数据，最终结果取决于进程执行的精确时序
  • 解决方法：互斥（Mutual Exclusion），确保同一时刻只有一个进程访问共享资源

临界区（Critical Section）：

  • 访问共享资源的代码段
  • 互斥要求：同一时刻最多一个进程在临界区内

互斥的实现方法：

  1. 关中断：进入临界区前关中断，退出后开中断

    • 简单但危险：关中断时间过长影响系统响应；用户程序不能关中断；多CPU无效

  2. 锁变量：用一个变量表示锁状态

    • 存在竞争条件：测试和设置不是原子操作

  3. 严格轮换法：进程轮流进入临界区

    • 忙等待，违反”空闲让进”

  4. Peterson算法：

    • 使用turn变量和flag数组
    • 满足互斥、空闲让进、有限等待
    • 软件解决方案，适用于两个进程

  5. TSL指令（测试并加锁）：

    • 硬件原子指令：测试并设置内存字
    • 进入临界区前执行TSL，退出后解锁
    • 忙等待

  6. 睡眠与唤醒：

    • sleep：进程阻塞等待
    • wakeup：唤醒等待的进程
    • 生产者-消费者问题

信号量（Semaphore）：

  • Dijkstra提出，用于进程同步和互斥
  • 一个整数变量，支持两个原子操作：
    • P操作（down/wait）：信号量减1，若<0则进程阻塞
    • V操作（up/signal）：信号量加1，若≤0则唤醒一个等待进程
  • 二元信号量（互斥锁）：初值为1，用于互斥
  • 计数信号量：初值为资源数，用于资源计数和同步
  • 生产者-消费者问题：用信号量解决（empty、full、mutex）

互斥量（Mutex）：

  • 二元信号量的简化形式，专门用于互斥
  • lock/unlock操作
  • 可支持递归锁、优先级继承

条件变量（Condition Variable）：

  • 与互斥量配合使用，用于等待某个条件成立
  • wait：释放互斥量并阻塞，被唤醒后重新获取互斥量
  • signal/broadcast：唤醒一个/所有等待的线程
  • 生产者-消费者问题的另一种实现

管程（Monitor）：

  • 高级同步原语，封装共享数据和操作
  • 管程内的过程互斥执行（同一时刻最多一个进程在管程内）
  • 包含条件变量，用于等待和通知
  • 语言级支持（Java的synchronized、C#的lock）

消息传递：

  • 进程通过发送和接收消息通信
  • 原语：send(destination, message)、receive(source, message)
  • 设计问题：
    • 有缓冲/无缓冲
    • 阻塞/非阻塞发送
    • 阻塞/非阻塞接收
    • 信箱（间接通信）

屏障（Barrier）：

  • 用于一组进程的同步
  • 所有进程到达屏障前都阻塞，最后一个到达后全部释放
  • 适用于分阶段并行计算

2.4 进程调度

调度时机：

  • 进程创建时
  • 进程退出时
  • 进程阻塞时
  • I/O中断发生时
  • 时钟中断发生时

调度算法分类：

  • 批处理系统：关注吞吐量和周转时间
  • 交互式系统：关注响应时间
  • 实时系统：关注截止时间

批处理调度算法：

  1. 先来先服务（FCFS）：按到达顺序调度，非抢占
    • 简单，平均等待时间可能很长（护航效应）
  2. 最短作业优先（SJF）：优先调度运行时间最短的作业，非抢占
    • 平均等待时间最优（所有作业同时到达时）
  3. 最短剩余时间优先（SRTN）：SJF的抢占版本，新作业到达时比较剩余时间
    • 平均周转时间更优

交互式调度算法：

  1. 时间片轮转（RR）：每个进程分配一个时间片，轮流执行
    • 公平，响应时间好
    • 时间片大小：太大→FCFS，太小→切换开销大
  2. 优先级调度：每个进程有优先级，优先调度高优先级进程
    • 可抢占/非抢占
    • 问题：低优先级进程饥饿（老化技术解决：随时间提升优先级）
  3. 多级队列：进程分为多个队列（如前台/后台），各队列独立调度
  4. 多级反馈队列（MLFQ）：
    • 多个队列，优先级递减，时间片递增
    • 新进程进入最高优先级队列
    • 时间片用完则降低优先级
    • I/O密集型进程保持高优先级（频繁阻塞，时间片用不完）
    • 动态调整，适应进程行为
  5. 彩票调度：给进程分配彩票，调度时随机抽取彩票
    • 持有彩票越多，被调度概率越大
    • 可转让彩票（协作进程）

实时调度：

  • 硬实时：必须在截止时间前完成，否则严重后果
  • 软实时：期望在截止时间前完成，偶尔超时可接受
  • 速率单调调度（RMS）：静态优先级，周期越短优先级越高
  • 最早截止时间优先（EDF）：动态优先级，截止时间越早优先级越高

调度算法评估：

  • 确定性建模：特定工作负载计算性能
  • 排队模型：利用概率论和排队论分析
  • 模拟：编写模拟器模拟系统行为
  • 实现：在真实系统中实现并测量

第3章 内存管理

3.1 无内存抽象

早期系统：

  • 程序直接访问物理内存
  • 内存中同时只能运行一个程序（除了特殊的多道程序设计）
  • 问题：程序地址与物理地址绑定，不灵活；程序间无隔离

多道程序设计：

  • 内存中同时存放多个程序，CPU在它们之间切换
  • 地址重定位：程序加载时修改地址（静态重定位）
  • 问题：程序可能访问其他程序的内存，无保护

3.2 地址空间

地址空间概念：

  • 进程可使用的地址集合，是对物理内存的抽象
  • 每个进程有独立的地址空间，相互隔离
  • 基址寄存器和界限寄存器：
    • 基址寄存器：进程物理内存起始地址
    • 界限寄存器：进程地址空间大小
    • 物理地址 = 虚拟地址 + 基址寄存器
    • 越界检查：虚拟地址 > 界限寄存器则触发异常

静态重定位 vs 动态重定位：

  • 静态重定位：加载时一次性修改所有地址，程序运行中不能移动
  • 动态重定位：运行时通过基址寄存器计算物理地址，程序可在内存中移动

3.3 交换技术

交换（Swapping）：

  • 将整个进程从内存换出到磁盘，或将磁盘上的进程换入内存
  • 用于内存不足时，增加多道程序度
  • 交换区：磁盘上专门用于交换的区域
  • 问题：交换开销大（整个进程换入换出）

内存分配：

  • 连续分配：为进程分配连续的物理内存
  • 分配算法：
    • 首次适配（First Fit）：从头找第一个足够大的空闲区
    • 下次适配（Next Fit）：从上次分配位置继续找
    • 最佳适配（Best Fit）：找最小的足够大的空闲区（产生小碎片）
    • 最差适配（Worst Fit）：找最大的空闲区
  • 内存紧缩（Compaction）：移动进程使空闲区合并，解决外部碎片

3.4 空闲内存管理

位图法：

  • 内存划分为固定大小的分配单元，每个单元对应位图中的一位
  • 0表示空闲，1表示已分配
  • 优点：简单
  • 缺点：分配时需搜索连续0位，开销大

链表法：

  • 用链表记录空闲区和已分配区
  • 每个节点：进程/空闲标志、起始地址、长度、下一节点指针
  • 分配时遍历链表找合适的空闲区
  • 释放时合并相邻空闲区

3.5 分页

分页（Paging）：

  • 虚拟地址空间划分为固定大小的页（Page，通常4KB）
  • 物理内存划分为同样大小的页框（Page Frame）
  • 虚拟页可映射到任意物理页框
  • 页表（Page Table）：记录虚拟页到物理页框的映射
  • 虚拟地址 = 页号 + 页内偏移
  • 物理地址 = 页框号 + 页内偏移

页表：

  • 每个进程有独立的页表
  • 页表基址寄存器（PTBR）指向当前进程页表
  • 页表项（PTE）包含：
    • 页框号
    • 存在位（Present）：该页是否在内存
    • 保护位（Protection）：读/写/执行权限
    • 修改位（Dirty）：该页是否被修改
    • 访问位（Accessed）：该页是否被访问
    • 禁止缓存位

快表（TLB，Translation Lookaside Buffer）：

  • 页表在内存中，每次地址转换需两次内存访问（一次查页表，一次取数据）
  • TLB是高速缓存，缓存最近使用的页表项
  • TLB命中：直接从TLB获取页框号，一次内存访问
  • TLB未命中：查页表，更新TLB
  • TLB替换策略：LRU、随机

多级页表：

  • 单级页表过大（32位地址4KB页需1M个PTE，4MB/进程）
  • 两级页表：页目录 + 页表
    • 虚拟地址 = 页目录索引 + 页表索引 + 页内偏移
    • 页目录项指向页表，页表项指向页框
    • 未使用的页表不分配，节省内存
  • 三级/四级页表：64位地址空间使用

倒排页表：

  • 每个物理页框对应一个页表项（而非每个虚拟页）
  • 页表大小与物理内存成正比，与虚拟地址空间无关
  • 查找需搜索整个页表（用哈希表加速）
  • 适用于大虚拟地址空间系统（64位）

3.6 页面置换算法

缺页中断：

  • 访问的页不在内存（存在位为0），触发缺页中断
  • 操作系统将所需页从磁盘调入内存
  • 若内存已满，需选择一页换出（页面置换）

页面置换算法：

  1. 最优页面置换（OPT）：

    • 置换未来最久不使用的页
    • 理论最优，但无法实现（需预知未来）
    • 作为其他算法的比较基准

  2. 最近未使用（NRU）：

    • 根据访问位和修改位分类：
      • 第0类：未访问，未修改
      • 第1类：未访问，已修改
      • 第2类：已访问，未修改
      • 第3类：已访问，已修改
    • 从编号最小的非空类中随机置换
    • 简单，性能一般

  3. 先进先出（FIFO）：

    • 置换最早进入内存的页
    • 简单，但可能置换常用页
    • Belady异常：增加页框数反而缺页率增加

  4. 第二次机会（Clock）：

    • FIFO的改进，检查最早页的访问位
    • 访问位为0则置换；为1则清零并移到队尾（给第二次机会）
    • 用环形链表实现（时钟算法）

  5. 最近最少使用（LRU）：

    • 置换最久未使用的页
    • 基于局部性原理，性能接近最优
    • 实现：
      • 计数器：每页维护计数器，访问时更新，置换最小的
      • 栈：维护页号栈，访问时移到栈顶，置换栈底
    • 硬件开销大，实际系统常用近似算法

  6. 工作集时钟算法：

    • 结合工作集和Clock算法
    • 工作集：进程在最近τ次内存访问中使用的页集合
    • 工作集置换：置换不在工作集中的页
    • 工作集时钟：用Clock算法扫描，检查访问位和是否在工作集中

全局置换 vs 局部置换：

  • 局部置换：每个进程只能从自己的页中置换
  • 全局置换：可从所有进程的页中置换（更灵活，但可能影响其他进程）

分配页框：

  • 平均分配：每个进程分配相同数量
  • 按比例分配：按进程大小分配
  • 优先级分配：按进程优先级分配

3.7 分段

分段（Segmentation）：

  • 程序由逻辑段组成（代码段、数据段、堆栈段等）
  • 每个段有独立的地址空间，段内连续编址
  • 虚拟地址 = 段号 + 段内偏移
  • 段表记录每段的基址和长度
  • 优点：符合程序逻辑结构、段可独立增长、便于共享和保护
  • 缺点：产生外部碎片

段页式：

  • 结合分段和分页
  • 虚拟地址 = 段号 + 页号 + 页内偏移
  • 段表项指向页表，页表项指向页框
  • 先分段（逻辑），再分页（物理）
  • 结合两者优点，是现代操作系统常用方式

3.8 虚拟内存

虚拟内存（Virtual Memory）：

  • 程序不必全部装入内存即可运行
  • 只将当前需要的部分装入内存，其余在磁盘上
  • 程序可使用比物理内存大得多的地址空间
  • 基于局部性原理：程序在一段时间内只访问部分代码和数据

虚拟内存的实现：

  • 请求分页：只在需要时调入页
  • 页面置换：内存满时换出不常用页
  • 缺页中断处理：从磁盘调入页

虚拟内存的优点：

  • 运行大程序（大于物理内存）
  • 提高多道程序度（更多进程同时在内存）
  • 减少I/O（只加载需要的部分）
  • 程序加载更快
  • 内存保护和隔离

虚拟内存的缺点：

  • 缺页中断开销大
  • 抖动（Thrashing）：频繁换入换出，系统效率急剧下降
    • 原因：进程太多，分配的页框太少，频繁缺页
    • 解决：减少进程数、工作集模型、挂起进程

第4章 文件系统

4.1 文件

文件概念：

  • 文件是相关信息的命名集合，存储在磁盘等持久存储介质上
  • 是操作系统对磁盘的抽象（替代扇区操作）

文件命名：

  • 文件名：标识文件的字符串
  • 扩展名：表示文件类型（.txt、.exe、.pdf等）
  • 不同系统命名规则不同（大小写敏感、长度限制、允许字符）

文件结构：

  • 无结构（字节序列）：UNIX/Linux/Windows，文件是字节流，结构由应用解释
  • 记录序列：文件由固定长度记录组成，每条记录有字段
  • 树：文件由记录树组成，记录有键，按键排序（早期系统）

文件类型：

  • 普通文件：ASCII文件、二进制文件
  • 目录文件：存储目录结构
  • 字符特殊文件：串行I/O设备（终端、打印机）
  • 块特殊文件：磁盘等块设备

文件属性：

  • 文件名、大小、创建时间、修改时间、访问时间
  • 所有者、组、权限（读/写/执行）
  • 标志：只读、隐藏、系统、归档等

文件操作：

  • create、delete、open、close、read、write、append
  • seek（随机访问）、get_attributes、set_attributes、rename

4.2 目录

目录概念：

  • 目录是包含文件和子目录的特殊文件
  • 目录项记录文件名和文件的位置信息（i节点号/索引节点）

目录结构：

  • 单级目录：所有文件在一个目录中（早期系统）
  • 两级目录：每个用户一个目录
  • 树状目录：层次结构，根目录下有子目录和文件（现代系统）
  • 无环图目录：允许文件/目录有多个父目录（通过链接）
  • 通用图目录：允许环路（需垃圾回收）

路径名：

  • 绝对路径：从根目录开始的完整路径（/usr/bin/ls）
  • 相对路径：从当前工作目录开始的路径（bin/ls）
  • 当前工作目录（CWD）：进程的默认目录

目录操作：

  • create、delete、opendir、closedir、readdir
  • rename、link（硬链接）、unlink（删除）

链接：

  • 硬链接：多个目录项指向同一个i节点，i节点引用计数
    • 不能跨文件系统，不能链接目录
  • 符号链接（软链接）：存储目标文件的路径名
    • 可跨文件系统，可链接目录
    • 目标删除后成为悬空链接

4.3 文件系统的实现

文件系统布局：

  • 磁盘分区：每个分区可有独立的文件系统
  • 引导块（Boot Block）：引导加载程序
  • 超级块（Superblock）：文件系统元数据（块大小、i节点数、空闲块数等）
  • 空闲块管理：位图或链表
  • i节点（索引节点）：每个文件一个i节点，存储文件属性和数据块指针
  • 数据块：存储文件内容和目录

i节点（inode）：

  • 存储文件的所有属性（除文件名外）：大小、所有者、权限、时间戳、数据块指针
  • 数据块指针：
    • 直接块：前12个直接指向数据块
    • 一次间接块：指向一个块，块内存储数据块指针
    • 二次间接块：指向一个块，块内存储一次间接块指针
    • 三次间接块：指向一个块，块内存储二次间接块指针
  • 文件名存储在目录项中，目录项包含文件名和i节点号

目录实现：

  • 简单方法：固定长度目录项，文件名固定长度
  • 改进方法：可变长度目录项，文件名可变
  • 目录项包含：i节点号、文件名长度、文件名
  • 大目录用哈希表加速查找

共享文件：

  • 硬链接：多个目录项指向同一i节点
  • 符号链接：存储路径
  • 副本：文件复制，修改不同步

4.4 文件系统管理和优化

磁盘空间管理：

  • 位图：每个块对应一位，0空闲1已分配
    • 简单，查找连续块方便
    • 位图本身占用空间
  • 链表：空闲块用链表链接
    • 查找连续块困难
  • 成组链接：空闲块分组，组内用链表，组间用索引（UNIX文件系统）

文件系统性能优化：

  • 高速缓存：缓存常用的磁盘块（缓冲区缓存）
    • 写策略：
      • 写直达（Write-through）：立即写磁盘，安全但慢
      • 写回（Write-back）：先写缓存，延迟写磁盘，快但可能丢失
  • 提前读：顺序访问时提前读取后续块
  • 减少磁盘寻道：
    • 块簇（Cluster）：连续块一起分配
    • i节点与数据块靠近
    • 磁盘碎片整理
  • 日志结构文件系统（LFS）：
    • 所有修改追加到日志末尾，顺序写
    • 定期清理（Segment Cleaning）
    • 提高写性能，适合闪存

文件系统一致性：

  • 崩溃可能导致文件系统不一致（i节点引用计数错误、空闲块位图错误）
  • 文件系统检查（fsck）：
    • 检查块一致性：i节点中的块 vs 位图
    • 检查i节点一致性：引用计数、链接数
    • 修复不一致
  • 日志文件系统（Journaling FS）：
    • 先写日志记录操作，再执行操作
    • 崩溃后根据日志恢复
    • ext3/ext4、NTFS、XFS等

4.5 文件系统实例

ext2/ext3/ext4：

  • Linux标准文件系统
  • ext2：无日志
  • ext3：增加日志
  • ext4：扩展ext3，支持更大文件和分区、延迟分配、多块分配、在线碎片整理

NTFS：

  • Windows标准文件系统
  • 支持大文件、Unicode文件名、日志、压缩、加密、访问控制
  • 主文件表（MFT）：存储所有文件和目录信息

FAT32/exFAT：

  • FAT（文件分配表）：简单，兼容性好
  • FAT32：最大文件4GB，最大分区2TB
  • exFAT：扩展FAT，支持大文件，适合闪存

ISO 9660：

  • CD-ROM文件系统

UDF：

  • DVD文件系统

第5章 输入/输出

5.1 I/O硬件原理

I/O设备分类：

  • 字符设备：按字节流访问（键盘、鼠标、串口、打印机）
  • 块设备：按固定大小块访问（磁盘、闪存）
  • 网络设备：特殊处理（套接字接口）

设备控制器：

  • I/O设备与系统总线之间的接口
  • 包含寄存器（数据寄存器、状态寄存器、控制寄存器）
  • CPU通过I/O端口或内存映射I/O访问控制器寄存器

I/O端口编址：

  • 独立I/O（Port-mapped I/O）：I/O端口有独立地址空间，用in/out指令访问
  • 内存映射I/O（Memory-mapped I/O）：I/O寄存器映射到内存地址空间，用普通内存访问指令
  • 混合方式：x86同时支持

I/O方式：

  1. 程序控制I/O（忙等待/轮询）：
    • CPU不断查询设备状态，直到设备就绪
    • 简单，但CPU利用率低（忙等待）
  2. 中断驱动I/O：
    • CPU启动I/O后继续执行其他任务
    • 设备完成后发中断，CPU在中断处理程序中处理数据
    • CPU利用率高，但每个字符/块都需中断
  3. DMA（直接存储器访问）：
    • DMA控制器直接在设备和内存间传输数据
    • CPU只需设置DMA参数（源地址、目的地址、长度）
    • 传输完成后DMA发中断
    • CPU不参与数据传输，适合大块数据传输

5.2 I/O软件原理

I/O软件目标：

  • 设备无关性：程序不依赖特定设备
  • 统一命名：设备名与物理设备无关
  • 错误处理：尽量在低层处理错误
  • 同步/异步传输：支持阻塞和非阻塞
  • 缓冲：减少I/O次数，匹配速度差异
  • 共享与独占：合理分配设备

I/O软件层次（自底向上）：

  1. 中断处理程序：处理设备中断，唤醒等待的驱动程序
  2. 设备驱动程序：与设备控制器通信，发送命令，处理设备特定操作
  3. 与设备无关的I/O软件：
    • 设备命名和保护
    • 块设备的块大小统一
    • 缓冲（块缓冲、字符缓冲）
    • 错误报告
    • 设备分配和释放
  4. 用户空间I/O软件：
    • 库函数（printf、read等）
    • 假脱机（Spooling）：打印机等独占设备的共享

缓冲（Buffering）：

  • 目的：匹配生产者和消费者的速度差异、减少I/O次数、支持提前读和延迟写
  • 单缓冲、双缓冲、循环缓冲
  • 块缓冲：缓存磁盘块
  • 字符缓冲：缓存字符设备数据

假脱机（Spooling）：

  • 独占设备（打印机）的共享方式
  • 多个进程的输出先送到磁盘缓冲区（Spool目录）
  • 守护进程依次从缓冲区取出打印
  • 类似的还有输入Spooling

5.4 磁盘

磁盘结构：

  • 盘片、磁道、扇区、柱面
  • 磁盘控制器：控制磁盘读写
  • CHS寻址：柱面-磁头-扇区
  • LBA寻址：逻辑块地址（现代磁盘）

磁盘性能参数：

  • 寻道时间：磁头移动到目标磁道的时间
  • 旋转延迟：等待目标扇区转到磁头下的时间（平均为半圈）
  • 传输时间：读取/写入数据的时间
  • 平均访问时间 = 寻道时间 + 旋转延迟 + 传输时间

磁盘调度算法：

  1. FCFS（先来先服务）：按请求顺序处理
    • 公平，寻道时间长
  2. SSTF（最短寻道时间优先）：选择离当前磁头最近的请求
    • 减少寻道时间，但可能饥饿
  3. SCAN（电梯算法）：磁头沿一个方向移动，处理沿途请求，到端点后反向
    • 类似电梯，公平，性能好
  4. C-SCAN（循环SCAN）：只在一个方向处理，到端点后立即回到起点（不处理回程）
    • 更均匀的等待时间
  5. LOOK：SCAN的改进，到最后一个请求就反向（不到磁盘端点）
  6. C-LOOK：C-SCAN的改进

错误处理：

  • 坏扇区：备用扇区替换
  • ECC（纠错码）：检测和纠正读取错误
  • 磁盘阵列（RAID）：通过冗余提高可靠性和性能

RAID（独立磁盘冗余阵列）：

  • RAID 0：条带化，无冗余，性能高，可靠性低
  • RAID 1：镜像，完全冗余，可靠性高，空间利用率50%
  • RAID 2：位级条带化+汉明码校验（已不用）
  • RAID 3：字节级条带化+奇偶校验
  • RAID 4：块级条带化+一个奇偶盘（奇偶盘瓶颈）
  • RAID 5：块级条带化+分布式奇偶校验（最常用）
  • RAID 6：双奇偶校验，可容忍两块磁盘故障
  • RAID 10：RAID 1+0，镜像+条带化

5.5 时钟

时钟（定时器）：

  • 硬件时钟：晶振产生固定频率信号
  • 可编程间隔定时器（PIT）：可设置频率
  • 时钟中断：定期触发，用于进程调度、时间片、统计、超时

时钟功能：

  • 维护系统时间（墙上时钟）
  • 进程调度（时间片轮转）
  • 定时器（alarm、sleep）
  • 统计CPU使用时间
  • 看门狗定时器

软件时钟：

  • 时钟中断处理程序维护软件时钟
  • 时钟队列：按触发时间排序的定时器链表
  • 每次时钟中断检查是否有定时器到期

5.6 键盘、鼠标和显示器

键盘：

  • 按键产生扫描码（按下和释放）
  • 键盘控制器将扫描码发给CPU（中断）
  • 键盘驱动将扫描码转换为ASCII码/字符
  • 行规则（Line Discipline）：处理特殊字符（退格、Ctrl+C等）、行缓冲

鼠标：

  • 移动产生相对位移（Δx, Δy）和按键状态
  • 鼠标驱动将位移转换为光标位置
  • 图形界面中鼠标事件传递给应用程序

显示器（图形设备）：

  • 帧缓冲区（Framebuffer）：存储屏幕像素数据
  • 显卡（GPU）：处理图形渲染
  • 显示模式：文本模式、图形模式
  • 分辨率、颜色深度、刷新率
  • 窗口系统：X11、Wayland、Windows GDI

第6章 死锁

6.1 死锁概述

死锁定义：

  • 一组进程中每个进程都等待其他进程所占有的资源，因而所有进程都永远无法继续执行
  • 死锁的进程不消耗CPU，但占用资源

资源类型：

  • 可抢占资源：可从占有进程强行抢占（CPU、内存）
  • 不可抢占资源：不能强行抢占，必须等待进程自愿释放（打印机、磁带机）
  • 死锁主要涉及不可抢占资源

资源获取顺序：

  1. 请求资源：若不可用则等待
  2. 使用资源
  3. 释放资源

6.2 死锁的四个必要条件

Coffman条件（死锁发生的四个必要条件，缺一不可）：

  1. 互斥条件：资源一次只能被一个进程占有
  2. 占有并等待条件：进程占有至少一个资源，又等待其他进程占有的资源
  3. 不可抢占条件：已占有的资源不能被强行抢占，只能自愿释放
  4. 循环等待条件：存在一个进程循环链，每个进程等待下一个进程占有的资源

6.3 死锁建模

资源分配图：

  • 顶点：进程（圆形）、资源类型（矩形，内有圆点表示实例数）
  • 边：
    • 资源→进程：占有边（进程占有该资源实例）
    • 进程→资源：请求边（进程请求该资源）
  • 若资源分配图中无环，则无死锁
  • 若有环：
    • 每种资源只有一个实例 → 死锁
    • 每种资源有多个实例 → 可能死锁（需进一步分析）

6.4 死锁处理策略

四种处理策略：

  1. 忽略死锁（鸵鸟算法）：假装死锁不会发生
  2. 死锁检测与恢复：允许死锁发生，检测后恢复
  3. 死锁避免：动态分配资源，确保不进入死锁状态
  4. 死锁预防：破坏死锁的四个必要条件之一

6.5 死锁检测与恢复

死锁检测算法：

  • 每种资源一个实例：检测资源分配图中是否有环
  • 每种资源多个实例：
    • 类似银行家算法的安全性检测
    • 找一个进程，其请求资源≤可用资源，假设其完成并释放资源
    • 重复，若所有进程都能完成则无死锁，否则有死锁

恢复方法：

  1. 抢占：从某个进程抢占资源给其他进程
    • 选择牺牲进程、回滚（恢复到安全状态）、防止饥饿
  2. 回滚：将进程回滚到之前的检查点，重新执行
  3. 杀死进程：终止一个或多个死锁进程
    • 选择代价最小的进程（优先级、已运行时间、剩余时间）
    • 可能需要杀死多个进程才能打破循环

6.6 死锁避免

安全状态：

  • 存在一个安全序列，按此序列分配资源，所有进程都能完成
  • 安全状态一定无死锁
  • 不安全状态可能死锁（不一定）

银行家算法（Dijkstra）：

  • 每个进程声明最大资源需求
  • 分配资源前检查：分配后系统是否仍处于安全状态
  • 若安全则分配，否则等待
  • 数据结构：
    • Available：可用资源数
    • Max：每个进程最大需求
    • Allocation：每个进程已分配
    • Need = Max - Allocation：每个进程还需
  • 安全性算法：找Need≤Available的进程，假设完成释放资源，重复

银行家算法的问题：

  • 需预知进程最大资源需求
  • 进程数和资源数固定
  • 进程必须在有限时间内释放资源
  • 实际系统中很少使用（条件太严格）

6.7 死锁预防

破坏四个必要条件之一：

  1. 破坏互斥条件：

    • 资源可同时被多个进程使用（如只读文件）
    • 不适用于所有资源（打印机必须互斥）

  2. 破坏占有并等待条件：

    • 进程一次性请求所有需要的资源，要么全部分配，要么都不分配
    • 缺点：资源浪费（长期占有不用的资源）、可能饥饿

  3. 破坏不可抢占条件：

    • 进程占有资源后请求新资源被拒绝时，释放已占有的所有资源
    • 以后重新请求所有资源
    • 缺点：实现复杂、可能丢失工作、开销大

  4. 破坏循环等待条件：

    • 对所有资源类型全局排序，进程必须按序号递增的顺序请求资源
    • 确保不会形成循环等待
    • 缺点：资源排序需合理，限制编程灵活性

两阶段加锁：

  • 数据库中的死锁预防方法
  • 增长阶段：只能加锁，不能解锁
  • 收缩阶段：只能解锁，不能加锁
  • 确保可串行化调度

第7章 虚拟化和云

7.1 虚拟化概述

虚拟化定义：

  • 在同一物理硬件上运行多个独立的虚拟机（VM），每个虚拟机运行自己的操作系统
  • 虚拟机监控器（VMM/Hypervisor）管理和分配物理资源

虚拟化的好处：

  • 资源整合：提高服务器利用率
  • 隔离：虚拟机间相互隔离，一个崩溃不影响其他
  • 迁移：虚拟机可在物理机间迁移（负载均衡、故障恢复）
  • 快照：保存虚拟机状态，可回滚
  • 多操作系统：同一硬件运行不同OS

7.2 虚拟化类型

Type 1（裸金属Hypervisor）：

  • Hypervisor直接运行在物理硬件上
  • 性能好，安全性高
  • 例：VMware ESXi、Microsoft Hyper-V、Xen、KVM（Linux内核模块）

Type 2（宿主Hypervisor）：

  • Hypervisor运行在宿主操作系统上
  • 安装方便，适合桌面
  • 例：VMware Workstation、VirtualBox、Parallels

容器虚拟化：

  • 不是完整虚拟机，而是在宿主OS内核上隔离的用户空间实例
  • 共享宿主OS内核，更轻量，启动更快
  • 例：Docker、LXC、Kubernetes

7.3 虚拟化技术

CPU虚拟化：

  • 陷入并模拟（Trap and Emulate）：敏感指令陷入VMM，VMM模拟执行
  • 二进制翻译（BT）：动态翻译客户机指令（VMware）
  • 硬件辅助虚拟化：Intel VT-x、AMD-V，提供VMX根模式/非根模式
    • VMCS（虚拟机控制结构）：保存虚拟机状态
    • VM Entry/VM Exit：进入/退出虚拟机

内存虚拟化：

  • 影子页表：VMM维护客户机虚拟地址到物理地址的映射
  • 硬件辅助：Intel EPT（扩展页表）、AMD NPT（嵌套页表）
    • 客户机页表（GVA→GPA）+ EPT（GPA→HPA），两次地址转换

I/O虚拟化：

  • 模拟设备：VMM模拟常见设备（IDE、网卡），客户机用标准驱动
  • 半虚拟化（Para-virtualization）：客户机驱动知道自己在虚拟机中，与VMM配合（Xen）
  • 直通设备（Passthrough）：将物理设备直接分配给虚拟机（IOMMU/VT-d）
  • SR-IOV：单根I/O虚拟化，一个物理设备可虚拟为多个虚拟功能

7.4 云计算

云服务模型：

  • IaaS（基础设施即服务）：提供虚拟机、存储、网络（AWS EC2、阿里云ECS）
  • PaaS（平台即服务）：提供开发平台和工具（Google App Engine、Heroku）
  • SaaS（软件即服务）：提供应用软件（Gmail、Office 365）

云部署模型：

  • 公有云：第三方提供商，多租户共享
  • 私有云：组织自建，专用
  • 混合云：公有云+私有云组合
  • 社区云：特定社区共享

云的关键技术：

  • 虚拟化：资源抽象和隔离
  • 分布式存储：对象存储（S3）、块存储、文件存储
  • 弹性伸缩：根据负载自动增减资源
  • 负载均衡：分发流量到多台服务器
  • 容器编排：Kubernetes管理容器集群
  • 无服务器计算（Serverless）：函数即服务（FaaS），按调用计费

第8章 多处理机系统

8.1 多处理机概述

多处理机分类：

  • UMA（一致内存访问）：所有CPU共享物理内存，访问时间一致（SMP）
  • NUMA（非一致内存访问）：CPU访问本地内存快，远程内存慢
  • 多处理机（Multiprocessor）：多个CPU共享内存
  • 多计算机（Multicomputer）：多个计算机通过网络互联，不共享内存（集群）

Flynn分类法：

  • SISD：单指令单数据（传统单处理器）
  • SIMD：单指令多数据（向量处理器、GPU）
  • MISD：多指令单数据（少见）
  • MIMD：多指令多数据（多处理机、多计算机）

8.2 对称多处理机（SMP）

SMP特点：

  • 所有CPU地位平等，共享内存和I/O
  • 每个CPU有自己的缓存（L1/L2）
  • 缓存一致性问题：一个CPU修改缓存中的数据，其他CPU的缓存副本需更新

缓存一致性协议：

  • MESI协议：每个缓存行有四种状态：
    • M（Modified）：已修改，与内存不一致，仅本缓存有
    • E（Exclusive）：独占，与内存一致，仅本缓存有
    • S（Shared）：共享，与内存一致，多个缓存有
    • I（Invalid）：无效
  • 读写操作触发状态转换和总线事务（BusRd、BusRdX、BusUpgr）
  • 监听协议：每个CPU监听总线上的事务，相应更新缓存状态

伪共享（False Sharing）：

  • 两个CPU访问同一缓存行中的不同变量
  • 一个CPU修改变量导致整个缓存行失效，另一个CPU需重新加载
  • 解决：变量对齐到不同缓存行、填充

8.3 多处理机调度

多处理机调度问题：

  • 进程分配到哪个CPU
  • 是否允许进程在CPU间迁移
  • 缓存亲和性：进程在同一CPU运行可利用缓存

调度方式：

  • 单队列调度：所有CPU共享一个就绪队列
    • 简单，负载均衡好
    • 锁竞争（多CPU同时操作队列需加锁）
    • 缓存亲和性差
  • 多队列调度：每个CPU有自己的就绪队列
    • 锁竞争小，缓存亲和性好
    • 负载可能不均衡，需负载均衡机制
    • Linux O(1)调度器、CFS使用每CPU运行队列

亲和性调度：

  • 软亲和性：调度器尽量让进程在同一CPU运行
  • 硬亲和性：进程绑定到特定CPU（sched_setaffinity）

多核调度挑战：

  • 核心间共享缓存（L3），调度需考虑缓存影响
  • 功耗和温度管理（DVFS、核心休眠）
  • 异构多核（ARM big.LITTLE）：高性能核心+低功耗核心，调度需匹配任务

8.4 多计算机系统（集群）

集群特点：

  • 多个独立计算机通过高速网络互联
  • 不共享内存，通过消息传递通信
  • 可扩展性好（数百/数千节点）
  • 成本低（用 commodity PC）

消息传递接口（MPI）：

  • 并行编程标准，用于多计算机
  • MPI_Send、MPI_Recv、MPI_Bcast、MPI_Reduce等
  • 进程间显式消息传递

分布式共享内存（DSM）：

  • 在多计算机上模拟共享内存
  • 页面级共享，通过网络传输页面
  • 类似虚拟内存，缺页时从远程节点获取
  • 一致性协议：写无效、写更新

第9章 安全

9.1 安全环境

安全目标：

  • 机密性（Confidentiality）：数据不被未授权访问
  • 完整性（Integrity）：数据不被未授权修改
  • 可用性（Availability）：系统和数据可被授权用户访问
  • 认证（Authentication）：确认用户/系统身份
  • 不可否认（Non-repudiation）：用户不能否认已执行的操作

威胁分类：

  • 中断：攻击可用性（破坏系统、切断网络）
  • 截获：攻击机密性（窃听、窃取数据）
  • 篡改：攻击完整性（修改数据）
  • 伪造：攻击认证（冒充身份、伪造数据）

攻击者类型：

  • 脚本小子：使用现成工具攻击
  • 黑客：有技术能力，主动寻找漏洞
  • 内部人员：有权限的内部人员攻击
  • 有组织犯罪：经济利益驱动
  • 国家支持：国家级网络攻击

9.2 密码学基础

（参见《计算机网络》第8章笔记）

  • 对称加密：DES、3DES、AES
  • 公钥加密：RSA、ECC
  • 散列函数：MD5、SHA-1、SHA-256
  • 数字签名：RSA签名、DSA、ECDSA
  • 证书和PKI：X.509、CA

9.3 用户认证

认证方法：

  1. 你知道什么：口令、PIN
  2. 你有什么：智能卡、令牌、手机
  3. 你是谁：指纹、虹膜、人脸、声纹（生物特征）

口令安全：

  • 口令选择：避免弱口令、字典词
  • 口令存储：散列+盐值（Salt），不存明文
  • 口令破解：字典攻击、暴力攻击、彩虹表
  • 多因素认证（MFA）：两种或以上认证方式组合

生物特征认证：

  • 指纹识别、人脸识别、虹膜识别、声纹识别
  • 误拒率（FRR）：合法用户被拒绝
  • 误纳率（FAR）：非法用户被接受
  • 等错误率（EER）：FRR=FAR时的错误率，越低越好

9.4 操作系统安全

保护机制：

  • 内核态/用户态：特权级分离，用户程序不能直接访问硬件
  • 系统调用：用户程序通过系统调用请求内核服务
  • 内存保护：虚拟内存隔离进程地址空间
  • 文件权限：UNIX rwx权限、ACL

访问控制：

  • 自主访问控制（DAC）：资源所有者决定谁可访问（UNIX权限）
  • 强制访问控制（MAC）：系统统一策略，所有主体和客体有安全标签（SELinux）
  • 基于角色的访问控制（RBAC）：按角色分配权限

可信计算基（TCB）：

  • 系统中负责安全的所有部分（硬件、内核、关键进程）
  • TCB越小越容易验证安全性
  • 微内核架构可减小TCB

恶意软件：

  • 病毒：附着在正常程序上，需用户执行传播
  • 蠕虫：自我复制，通过网络传播，无需用户干预
  • 木马：伪装成正常程序，隐藏恶意功能
  • 勒索软件：加密用户文件，勒索赎金
  • 间谍软件：窃取用户信息
  • Rootkit：隐藏自身和其他恶意软件，获取root权限
  • 僵尸网络（Botnet）：被控制的计算机网络，用于DDoS、垃圾邮件

安全机制：

  • 防火墙：过滤网络流量
  • 入侵检测系统（IDS）/入侵防御系统（IPS）
  • 杀毒软件：特征码检测、启发式检测、行为检测
  • 地址空间布局随机化（ASLR）：随机化内存布局，防止缓冲区溢出攻击
  • 数据执行保护（DEP/NX）：标记数据页不可执行
  • 栈保护（Stack Canary）：检测栈溢出

9.5 网络安全

（参见《计算机网络》第8章笔记）

  • 防火墙：包过滤、状态检测、应用层网关
  • DDoS攻击和防御
  • SSL/TLS：安全通信
  • IPsec/VPN：网络层安全
  • 无线网络安全：WEP/WPA/WPA2/WPA3

  • 虚拟内存：分页，页大小4KB（大页支持）
  • 工作集：进程当前在物理内存中的页集合
  • 段对象：共享内存
  • 内存映射文件：将文件映射到地址空间

Windows I/O系统：

  • I/O管理器：统一I/O请求处理
  • IRP（I/O请求包）：I/O请求的数据结构
  • 设备驱动分层：功能驱动、过滤驱动、总线驱动
  • 即插即用（PnP）：自动检测和配置设备
  • 电源管理：ACPI

Windows文件系统：NTFS：

  • 支持大文件、Unicode、日志、压缩、加密、配额、硬链接/软链接
  • 主文件表（MFT）：存储所有文件和目录信息
  • 数据流：文件可有多个数据流（默认数据流+命名数据流）

Windows注册表：

  • 系统配置数据库，替代INI文件
  • 层次结构，键和值
  • 根键：HKEY_LOCAL_MACHINE、HKEY_CURRENT_USER等

第12章 操作系统设计

12.1 操作系统设计问题

设计目标：

  • 简单性 vs 功能丰富
  • 性能 vs 可维护性
  • 兼容性 vs 现代化
  • 安全性 vs 易用性

机制与策略分离：

  • 机制（Mechanism）：如何做（如调度算法框架）
  • 策略（Policy）：做什么（如优先级规则）
  • 分离使策略可灵活调整，不影响机制

12.2 内核结构

单体内核（Monolithic Kernel）：

  • 所有OS服务在内核中，运行在内核态
  • 优点：性能好（无进程间通信开销）
  • 缺点：庞大复杂、可维护性差、一个模块崩溃影响整个系统
  • 例：Linux、传统UNIX

微内核（Microkernel）：

  • 内核只保留最基本功能（进程间通信、地址空间、基本调度）
  • 其他服务（文件系统、设备驱动、网络）作为用户态进程
  • 优点：小而可靠、易于扩展、服务隔离（一个崩溃不影响其他）
  • 缺点：性能差（频繁用户态/内核态切换和IPC）
  • 例：Minix、QNX、Mach

外核（Exokernel）：

  • 内核只负责资源隔离和保护，不提供抽象
  • 应用程序直接管理硬件资源（库操作系统）
  • 最大化性能和灵活性
  • 研究项目，未广泛使用

混合内核：

  • 结合单体和微内核特点
  • Windows NT：微内核设计思想，但驱动在内核态
  • macOS XNU：Mach微内核 + BSD单体 + I/O Kit

12.3 可靠性和安全性

容错：

  • 硬件冗余：RAID、双电源、热备
  • 软件容错：检查点、回滚、重试
  • 拜占庭容错：处理任意故障（包括恶意）

形式化验证：

  • 用数学方法证明系统正确性
  • 适用于安全关键系统（航空、医疗、核控制）
  • 成本高，难以应用于大型系统

12.4 性能

性能指标：

  • 吞吐量：单位时间完成的任务数
  • 响应时间：从请求到响应的时间
  • 利用率：资源使用比例
  • 周转时间：从提交到完成的时间

性能优化：

  • 缓存：减少慢速访问
  • 批处理：合并操作减少开销
  • 并行：多CPU/多线程并行处理
  • 异步：非阻塞操作提高利用率
  • 局部性：利用时间和空间局部性
