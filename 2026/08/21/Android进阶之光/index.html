Android进阶之光

Android进阶之光

作者：刘望舒
全书共11章，493页，涵盖Android新特性、Material Design、View体系、多线程、网络框架、设计模式、事件总线、RxJava、依赖注入、应用架构和系统架构。

第1章 Android新特性

1.1 Android 5.0新特性

Android 5.0（Lollipop）是Android历史上的重大版本更新，引入了Material Design设计语言。

主要新特性：

  • Material Design：全新的设计语言，强调质感、阴影、动画和过渡效果
  • RecyclerView：取代ListView和GridView，更灵活、更高效的列表控件，强制使用ViewHolder模式
  • CardView：卡片式布局容器，自带圆角和阴影效果
  • Notification升级：支持三种通知样式（普通、大文本、大图片），锁屏显示通知，优先级设置
  • Toolbar：取代ActionBar，更灵活的导航栏控件
  • Palette：从图片中提取颜色，实现界面色调与图片协调
  • JobScheduler：统一的任务调度API，优化电池寿命
  • ART运行时：取代Dalvik，采用AOT（Ahead-Of-Time）编译，提升应用性能

1.2 Android 6.0新特性

Android 6.0（Marshmallow）的核心变化是运行时权限机制。

主要新特性：

  • 运行时权限：危险权限不再在安装时授予，而是在运行时动态申请。用户可以随时在设置中撤销权限。危险权限分为9组：日历、相机、通讯录、位置、麦克风、电话、传感器、短信、存储。
  • Doze模式：设备未充电、屏幕关闭一段时间后进入低功耗模式，限制网络访问和后台任务
  • App Standby：长期未使用的应用进入待机状态，限制网络访问
  • 文本选择：应用内文本选择时显示相关操作（如翻译、搜索）
  • 指纹认证：原生指纹识别API
  • 低功耗蓝牙：增强BLE支持

1.3 Android 7.0新特性

Android 7.0（Nougat）引入了多窗口模式。

主要新特性：

  • 多窗口模式：支持分屏、画中画（Android TV）、自由形状模式。Activity可配置resizeableActivity属性
  • 通知增强：直接回复（Inline Reply）、捆绑通知（Notification Groups）、自定义通知视图
  • Data Saver：数据节省模式，限制后台数据使用
  • Quick Settings：快速设置面板可自定义
  • 多语言支持：应用可设置不同语言，系统按优先级匹配
  • Vulkan API：新一代3D图形API，更低的CPU开销
  • Project Svelte：优化后台进程，减少内存占用

第2章 Material Design

2.1 Material Design概述

Material Design是Google推出的设计语言，核心思想是将物理世界的材质质感引入数字界面。

核心原则：

  • 材质与空间：界面元素是具有厚度的”纸片”，通过z轴高度产生阴影
  • 动画：动效是有意义的，引导用户注意力，提供反馈
  • 样式：大胆的色彩、排版和图标
  • 组件：统一的设计组件库

2.2 Design Support Library常用控件

Snackbar：轻量级提示，显示在屏幕底部，可包含一个操作按钮，自动消失。与Toast的区别：Snackbar可滑动消失，可包含操作。

TextInputLayout：包裹EditText，实现浮动标签效果（输入时hint上浮为标签），支持错误提示。

FloatingActionButton：浮动操作按钮，圆形按钮，带阴影，通常用于页面主要操作。

TabLayout：选项卡布局，配合ViewPager实现页面切换，支持可滚动标签和固定标签。

NavigationView：抽屉菜单，包含头部布局和菜单列表，配合DrawerLayout使用。

CoordinatorLayout：超级FrameLayout，协调子View之间的交互。通过Behavior机制实现：

  • AppBarLayout折叠效果（Toolbar随滚动隐藏/显示）
  • CollapsingToolbarLayout折叠工具栏（视差效果、标题缩放）
  • Snackbar与FAB的协调（Snackbar出现时FAB上移）

第3章 View体系与自定义View

3.1 View与ViewGroup

View是所有控件的基类，ViewGroup继承自View，是控件的容器。View树的根是DecorView。

3.2 坐标系

  • Android坐标系：以屏幕左上角为原点，向右为x轴正方向，向下为y轴正方向
  • View坐标系：以父容器左上角为原点，View的位置由left、top、right、bottom确定
  • x/y：View左上角的当前坐标 = left + translationX
  • getRawX/getRawY：触摸点相对于屏幕的坐标
  • getX/getY：触摸点相对于View左上角的坐标

3.3 View的滑动

六种实现View滑动的方式：

  1. layout()方法：在onTouchEvent中调用layout(l, t, r, b)重新设置位置
  2. offsetLeftAndRight/offsetTopAndBottom：系统提供的便捷方法，同时更新left/right或top/bottom
  3. LayoutParams：修改布局参数（如margin），需调用requestLayout
  4. 动画：View动画（影像移动）或属性动画（真正改变位置）
  5. scrollTo/scrollBy：滑动View内容，scrollTo绝对滑动，scrollBy相对滑动
  6. Scroller：弹性滑动，配合computeScroll实现平滑滚动

3.4 属性动画

属性动画（Android 3.0+）可对任意对象的任意属性做动画。核心类：ValueAnimator、ObjectAnimator、AnimatorSet。插值器（Interpolator）控制动画速率，估值器（TypeEvaluator）计算属性值。

3.5 解析Scroller

Scroller本身不产生滑动，需配合View的computeScroll方法：

  1. startScroll(startX, startY, dx, dy, duration)开始滑动
  2. invalidate触发重绘 → draw → computeScroll
  3. computeScroll中调用scroller.computeScrollOffset()获取当前位置
  4. scrollTo移动到当前位置，postInvalidate继续重绘
  5. 直到computeScrollOffset返回false，滑动结束

3.6 View的事件分发机制

事件分发的三个核心方法：

  • dispatchTouchEvent：分发事件
  • onInterceptTouchEvent：判断是否拦截（仅ViewGroup有）
  • onTouchEvent：处理事件

传递顺序：Activity → Window → DecorView → ViewGroup → View。如果所有View都不消费，最终回到Activity的onTouchEvent。

关键结论：

  • 同一事件序列一旦被某个View拦截消费，后续事件直接交给它
  • View的onTouchEvent默认返回true（可点击时），不可点击时返回false
  • onTouchListener优先级高于onTouchEvent，onClickListener最低
  • DOWN事件不消费，则后续事件不再交给该View

3.7 View的工作流程

measure过程：测量View大小。View通过onMeasure完成，ViewGroup需遍历测量子元素。getDefaultSize中AT_MOST和EXACTLY都返回specSize，因此自定义View需重写onMeasure处理wrap_content。

layout过程：确定View位置。setFrame设置四个顶点，onLayout确定子元素位置。

draw过程：绘制View。顺序：背景 → onDraw → dispatchDraw（子元素）→ 装饰（滚动条）。

MeasureSpec：32位int，高2位SpecMode（UNSPECIFIED/EXACTLY/AT_MOST），低30位SpecSize。

3.8 自定义View

四种类型：

  1. 继承View重写onDraw：不规则效果
  2. 继承特定ViewGroup：组合布局
  3. 继承特定View：扩展已有控件
  4. 继承ViewGroup重写onMeasure/onLayout：自定义布局

注意事项：支持wrap_content、支持padding、线程/动画在onDetachedFromWindow停止、处理滑动冲突。

第4章 多线程编程

4.1 线程基础

进程与线程：进程是资源分配的最小单位，线程是CPU调度的最小单位。一个进程包含多个线程，共享进程资源。

线程状态：新建（New）、就绪（Runnable）、运行（Running）、阻塞（Blocked）、等待（Waiting）、超时等待（Timed Waiting）、终止（Terminated）。

创建线程：继承Thread、实现Runnable、实现Callable（有返回值）。

理解中断：interrupt()设置中断标志，isInterrupted()检查标志，interrupted()检查并清除标志。阻塞方法（sleep/wait/join）会抛出InterruptedException并清除标志。

安全终止线程：使用中断标志或volatile boolean标志，在循环中检查，优雅退出。

4.2 同步

重入锁（ReentrantLock）：可重入的互斥锁，支持公平锁和非公平锁，可绑定多个Condition。

同步方法/同步代码块：synchronized关键字，基于对象监视器（Monitor）实现，可重入。

volatile：保证可见性（修改立即刷新到主存）和有序性（禁止指令重排），不保证原子性。适用于状态标志位、双重检查锁定。

4.3 阻塞队列

阻塞队列在队列为空时获取操作阻塞，队列满时插入操作阻塞。

Java中的阻塞队列：

  • ArrayBlockingQueue：数组实现的有界队列
  • LinkedBlockingQueue：链表实现的有界/无界队列
  • PriorityBlockingQueue：支持优先级的无界队列
  • DelayQueue：延迟获取的无界队列
  • SynchronousQueue：不存储元素的队列，直接传递
  • LinkedTransferQueue：链表实现的无界TransferQueue
  • LinkedBlockingDeque：链表实现的双向阻塞队列

4.4 线程池

ThreadPoolExecutor核心参数：corePoolSize（核心线程数）、maximumPoolSize（最大线程数）、keepAliveTime（非核心线程超时）、unit（时间单位）、workQueue（任务队列）、threadFactory（线程工厂）、handler（拒绝策略）。

处理流程：核心线程未满→创建核心线程；核心线程满且队列未满→入队；队列满且未达最大线程→创建非核心线程；都满→执行拒绝策略。

四种线程池：FixedThreadPool（固定线程数）、CachedThreadPool（按需创建）、ScheduledThreadPool（定时任务）、SingleThreadExecutor（单线程）。

4.5 AsyncTask的原理

AsyncTask封装了线程池和Handler。内部有SerialExecutor（串行执行器）和THREAD_POOL_EXECUTOR（实际执行线程池），以及InternalHandler（切换到主线程）。

执行流程：execute → executeOnExecutor → SerialExecutor排队 → 取出任务交THREAD_POOL_EXECUTOR执行 → FutureTask.run → doInBackground → publishProgress → Handler发送消息 → onProgressUpdate/onPostExecute。

第5章 网络编程与网络框架

5.1 网络分层

OSI七层模型：物理层、数据链路层、网络层、传输层、会话层、表示层、应用层。
TCP/IP四层模型：网络接口层、网际层（IP）、传输层（TCP/UDP）、应用层（HTTP/FTP/DNS等）。

5.2 TCP的三次握手与四次挥手

三次握手（建立连接）：

  1. 客户端发送SYN（seq=x），进入SYN_SENT状态
  2. 服务端回复SYN+ACK（seq=y, ack=x+1），进入SYN_RCVD状态
  3. 客户端回复ACK（ack=y+1），双方进入ESTABLISHED状态

四次挥手（断开连接）：

  1. 主动方发送FIN，进入FIN_WAIT_1
  2. 被动方回复ACK，进入CLOSE_WAIT，主动方进入FIN_WAIT_2
  3. 被动方发送FIN，进入LAST_ACK
  4. 主动方回复ACK，进入TIME_WAIT（等待2MSL），被动方关闭

5.3 HTTP协议原理

HTTP请求报文：请求行（方法+URL+版本）、请求头、空行、请求体。
HTTP响应报文：状态行（版本+状态码+原因短语）、响应头、空行、响应体。

常见状态码：200 OK、301永久重定向、302临时重定向、304未修改、400请求错误、401未授权、403禁止、404未找到、500服务器错误、502网关错误、503服务不可用。

HTTP消息报头：通用头（Cache-Control、Connection）、请求头（Host、User-Agent、Accept、Cookie、Authorization）、响应头（Server、Set-Cookie、Content-Type、Content-Length）、实体头（Content-Type、Content-Encoding、Content-Length、Last-Modified、ETag）。

5.4 HttpClient与HttpURLConnection

HttpClient：Apache提供，API丰富，但Android 6.0已移除。
HttpURLConnection：Java原生，轻量，Android推荐使用。支持GZIP压缩、连接池、缓存。

5.5 解析Volley

Volley是Google推出的网络库，适合小数据量、高频率的网络请求。

核心组件：

  • RequestQueue：请求队列，管理所有请求的调度
  • Request：请求类（StringRequest、JsonObjectRequest、ImageRequest）
  • CacheDispatcher：缓存调度线程
  • NetworkDispatcher：网络调度线程（默认4个）
  • Cache：缓存接口（DiskBasedCache实现）
  • Network：网络接口（BasicNetwork实现，基于HttpURLConnection）

工作流程：请求加入队列 → 缓存线程检查缓存 → 命中则解析返回；未命中交网络线程 → 网络请求 → 解析响应 → 写入缓存 → 回调主线程。

5.6 解析OkHttp

OkHttp是Square出品的高效HTTP客户端，Android主流网络库。

核心特性：

  • 支持HTTP/2和SPDY，多路复用
  • 连接池复用，减少延迟
  • GZIP压缩，减少流量
  • 响应缓存，避免重复请求
  • 自动重连和重定向
  • 拦截器机制（Interceptor）

核心类：OkHttpClient（客户端）、Request（请求）、Response（响应）、Call（调用）、Interceptor（拦截器）、Dispatcher（调度器）。

工作流程：client.newCall(request) → RealCall → Dispatcher调度 → 拦截器链（应用拦截器→重试重定向→桥接→缓存→连接→网络）→ 服务器响应 → 反向返回。

5.7 解析Retrofit

Retrofit是Square出品的类型安全的HTTP客户端，基于OkHttp，通过注解定义API接口。

核心特性：

  • 注解定义请求（GET/POST/PUT/DELETE等）
  • 支持多种转换器（Gson、Jackson、Moshi、Protobuf等）
  • 支持RxJava/Call适配器
  • 支持同步和异步调用

核心原理：通过动态代理将接口注解解析为Request，交给OkHttp执行，通过Converter将响应转换为Java对象。

第6章 设计模式

6.1 设计模式六大原则

  1. 单一职责原则（SRP）：一个类只做一件事
  2. 开闭原则（OCP）：对扩展开放，对修改关闭
  3. 里氏替换原则（LSP）：子类可替换父类
  4. 依赖倒置原则（DIP）：依赖抽象，不依赖具体
  5. 接口隔离原则（ISP）：接口要小而专，不强迫依赖不需要的方法
  6. 迪米特法则（LoD）：最少知识，减少类间耦合

6.2 创建型设计模式

  • 单例模式：确保唯一实例。饿汉式、懒汉式（同步锁）、双重检查锁定（DCL）、静态内部类、枚举。
  • 简单工厂模式：一个工厂类根据参数创建不同产品
  • 工厂方法模式：每个产品对应一个工厂，抽象工厂接口
  • 建造者模式：分步构建复杂对象，如AlertDialog.Builder

6.3 结构型设计模式

  • 代理模式：通过代理控制对真实对象的访问。静态代理、动态代理（JDK/CGLIB）。
  • 装饰模式：动态给对象添加职责，如Java IO流
  • 外观模式：统一接口封装子系统，简化调用
  • 享元模式：共享细粒度对象，减少内存，如String常量池、消息池

6.4 行为型设计模式

  • 策略模式：封装算法族，可互换使用，如动画插值器
  • 模板方法模式：定义算法骨架，子类实现具体步骤
  • 观察者模式：一对多依赖，状态变化自动通知，如EventBus、LiveData

第7章 事件总线

7.1 解析EventBus

EventBus是GreenRobot出品的发布/订阅事件总线，用于组件间解耦通信。

核心概念：

  • Event：事件对象，任意POJO
  • Publisher：发布者，调用post()发送事件
  • Subscriber：订阅者，通过@Subscribe注解标注方法
  • ThreadMode：线程模式（POSTING、MAIN、BACKGROUND、ASYNC）

使用步骤：

  1. 定义事件类
  2. 注册/注销：onCreate中register，onDestroy中unregister
  3. 订阅方法：@Subscribe(threadMode = ThreadMode.MAIN)
  4. 发布事件：EventBus.getDefault().post(event)

核心原理：

  • 注册时通过反射收集订阅方法（@Subscribe注解），存入SubscriptionsByEventType
  • post时根据事件类型查找订阅者，通过线程模式决定在哪个线程执行
  • 粘性事件（Sticky Event）：先发布后订阅也能收到

7.2 解析otto

otto是Square出品的事件总线，基于Guava的EventBus，已停止维护，被EventBus取代。核心思想与EventBus类似，使用@Produce和@Subscribe注解。

第8章 函数响应式编程

8.1 RxJava基本用法

RxJava是响应式编程库，基于观察者模式，实现异步操作的优雅处理。

核心角色：

  • Observable：被观察者，发射事件流
  • Observer/Subscriber：观察者，接收事件
  • Operator：操作符，变换/过滤/组合事件流
  • Scheduler：调度器，控制线程

基本实现：

8.2 RxJava的Subject

Subject既是Observable也是Observer，桥接非响应式世界和响应式世界。

  • PublishSubject：只接收订阅后发射的事件
  • BehaviorSubject：接收订阅前最近一个事件和后续事件
  • ReplaySubject：缓存所有事件，订阅时重放
  • AsyncSubject：只发射最后一个事件

8.3 RxJava操作符入门

创建操作符：create、just、fromArray、fromIterable、range、interval、timer、defer、empty、never、error。

变换操作符：map（类型转换）、flatMap（一对多，不保证顺序）、concatMap（保证顺序）、buffer（打包成列表）、scan（累加）、window（打包成Observable）。

过滤操作符：filter、take、takeLast、skip、skipLast、elementAt、distinct、distinctUntilChanged、throttleFirst（防抖）、throttleLast、debounce、timeout。

组合操作符：merge（合并，可能交错）、concat（连接，按顺序）、zip（配对组合）、combineLatest（最新组合）、startWith、mergeDelayError。

辅助操作符：delay、doOnNext、doOnComplete、doOnError、subscribeOn、observeOn、timeout、retry、repeat。

错误处理操作符：onErrorReturn、onErrorResumeNext、retry、retryWhen。

8.4 RxJava的线程控制

  • subscribeOn：指定Observable发射事件的线程（上游线程），多次调用只有第一次有效
  • observeOn：指定Observer接收事件的线程（下游线程），每次调用都切换下游线程
  • 常用Scheduler：Schedulers.io()（IO线程，适合网络/磁盘）、Schedulers.computation()（计算线程，适合CPU密集）、Schedulers.newThread()、AndroidSchedulers.mainThread()（主线程）

8.5 RxJava的使用场景

  • 结合OkHttp/Retrofit访问网络，链式处理请求和响应
  • 用RxBus替代EventBus（PublishSubject实现事件总线）
  • 防抖搜索（debounce）
  • 定时任务（interval/timer）
  • 合并多个请求（zip/merge）

8.6 RxJava源码解析

订阅过程：Observable.subscribe → ObservableSubscribeOn.subscribe（切换上游线程）→ 实际Observable.subscribe → 发射事件。

变换过程：map操作符创建ObservableMap，订阅时创建MapObserver，onNext中调用function.apply变换后传递给下游。

线程切换过程：subscribeOn通过SubscribeOnObserver在指定线程调用上游subscribe；observeOn通过ObserveOnObserver将事件投递到指定线程的Scheduler。

第9章 注解与依赖注入框架

9.1 注解

注解分类：

  • 标准注解：@Override、@Deprecated、@SuppressWarnings
  • 元注解：@Retention（保留策略：SOURCE/CLASS/RUNTIME）、@Target（作用目标）、@Inherited（可继承）、@Documented
  • 自定义注解：通过@interface定义

定义注解：

注解处理器：编译期处理注解，生成代码（如ButterKnife、Dagger2）。继承AbstractProcessor，process方法中处理注解元素，通过JavaPoet生成Java代码。

9.2 依赖注入的原理

控制反转（IoC）：对象的依赖由外部容器注入，而非自己创建。
依赖注入（DI）：IoC的一种实现方式，通过构造器、setter、接口注入依赖。

实现方式：

  • 编译期注解处理生成代码（ButterKnife、Dagger2）
  • 运行期反射（早期RoboGuice）
  • 运行期字节码增强

9.3 依赖注入框架

ButterKnife：View绑定框架，通过@BindView注解绑定View，编译期生成绑定代码，避免findViewById。支持@OnClick、@OnItemClick等事件绑定。

Dagger2：Google出品的依赖注入框架，编译期生成代码，无反射开销。

  • @Inject：标注需要注入的依赖或构造函数
  • @Module：提供依赖的模块
  • @Provides：Module中提供依赖的方法
  • @Component：注入器，连接Module和注入目标
  • @Singleton：单例作用域
  • @Subcomponent：子组件

第10章 应用架构设计

10.1 MVC模式

MVC（Model-View-Controller）：

  • Model：数据模型，处理业务逻辑
  • View：视图，界面展示
  • Controller：控制器，处理用户交互，更新Model和View

Android中Activity常承担Controller和部分View职责，导致Activity臃肿。

10.2 MVP模式

MVP（Model-View-Presenter）：

  • Model：数据模型，业务逻辑
  • View：视图接口，Activity/Fragment实现，只负责UI展示
  • Presenter：主持者，连接Model和View，处理业务逻辑

特点：View与Model完全解耦，通过Presenter通信。View通过接口暴露方法，Presenter调用View接口更新UI。便于单元测试。

MVP结合RxJava和Dagger2：RxJava处理异步数据流，Dagger2注入依赖，形成完整的架构体系。

10.3 MVVM模式

MVVM（Model-View-ViewModel）：

  • Model：数据模型
  • View：视图，观察ViewModel的数据变化
  • ViewModel：视图模型，暴露可观察的数据，处理业务逻辑

Data Binding：Google推出的数据绑定库，实现View和数据的双向绑定。

  • 在布局中通过@{}绑定数据
  • 通过@={}实现双向绑定
  • 支持事件绑定、表达式、自定义属性

应用Data Binding：减少findViewById和样板代码，实现数据驱动UI。结合LiveData/ViewModel形成Jetpack架构。

第11章 系统架构与MediaPlayer框架

11.1 Android系统架构

Android系统分为四层：

  1. 应用层：应用程序（Java/Kotlin）
  2. 应用框架层：Framework API（ActivityManager、WindowManager、ContentProvider等）
  3. 系统运行库层：C/C++库（SurfaceFlinger、MediaPlayer、SQLite、OpenGL）+ Android运行时（ART/Dalvik）
  4. Linux内核层：驱动、进程管理、内存管理、网络协议栈

11.2 Android系统源码目录

  • **app/**：核心应用（Contacts、Phone等）
  • **frameworks/**：框架层（base/core、base/services、base/media、native等）
  • **system/**：系统组件（core、media、netd等）
  • **hardware/**：硬件抽象层（HAL）
  • **external/**：第三方库
  • **packages/**：应用包
  • **art/**：ART虚拟机
  • **dalvik/**：Dalvik虚拟机
  • **kernel/**：Linux内核
  • **build/**：编译系统
  • **development/**：开发工具
  • **prebuilts/**：预编译工具链

11.3 SourceInsights使用

SourceInsight是代码阅读和编辑工具，支持符号跳转、引用查找、调用关系图。适合阅读Android源码这种大型项目。

11.4 MediaPlayer框架

Java Framework层：android.media.MediaPlayer，提供播放控制API。通过JNI调用Native层。

JNI层：android_media_MediaPlayer.cpp，桥接Java和Native层。

Native层：

  • MediaPlayer：C++客户端，通过Binder与服务端通信
  • IMediaPlayerService：服务端Binder接口
  • MediaPlayerService：运行在mediaserver进程，管理所有播放器实例
  • MediaPlayerService::Client：每个播放器的服务端代理
  • AwesomePlayer/NuPlayer：实际播放器，处理解码和渲染

播放流程：Java MediaPlayer → JNI → Native MediaPlayer → Binder → MediaPlayerService → Client → AwesomePlayer/NuPlayer → OMXCodec解码 → AudioTrack/Surface渲染。

读书笔记总结

《Android进阶之光》是一本面向中高级Android开发者的进阶书籍，涵盖了从UI新特性、Material Design、View体系、多线程、网络框架到设计模式、事件总线、RxJava、依赖注入和应用架构的全方位知识。

全书知识脉络：

  1. UI层（第1-3章）：Android新特性、Material Design控件、View体系与自定义View
  2. 并发与网络（第4-5章）：多线程编程、线程池、HTTP协议、Volley/OkHttp/Retrofit
  3. 设计与模式（第6-9章）：设计模式、事件总线、RxJava响应式编程、注解与依赖注入
  4. 架构与系统（第10-11章）：MVC/MVP/MVVM架构、Android系统架构与MediaPlayer框架

学习建议：

  • 第3章（View体系）和第5章（网络框架）是面试高频考点，建议重点掌握
  • 第8章（RxJava）是理解响应式编程的关键，建议动手实践
  • 第10章（应用架构）是从开发者向架构师进阶的必经之路
  • 第11章（系统架构）为深入Framework源码打下基础

这本书适合有一定Android开发基础、希望系统提升技术深度的开发者阅读。
